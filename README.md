# 乡e家 · 县乡村家庭财富管理服务平台

给**县乡村家庭**用的一个本地站点，两块内容：

| 页面 | 是什么 | 打开方式 |
|---|---|---|
| **`/`（主页面）** | **导航层**：六张入口卡（新手引导 / 智能体 / 知识图谱 / 模拟投资 / 组合体检 / 预测台账）+ 一张「我的画像」回显卡 | 起服务后访问 `/` |
| **`/agent`（智能体）** | 小模型 Kronos 出预测 → 结果回灌大模型 → 大模型给方向 + **强制风险提示**，回答带上你的画像 | 主页那张卡 |
| **`/onboarding`（新手引导）** | 分步走：这是什么地方 / 三步上手 / 模型做不到什么 / **最后一步就是那张投资画像** | 第一次来**自动跳一次**；之后只能从主页那张卡进 |
| **`/profile`（我的画像）** | 投资兴趣 / 风险偏好 / 资产区间 / 收入区间。只写进你这台机器的 `localStorage` | 主页那张画像卡，可反复改 |
| **`/game`（模拟投资）** | 填一局**虚拟本金**，拿**真行情**回看"那天买了现在赚多少"，或今天按真价建仓逐日跟踪 | 主页那张卡 |
| **`/dash`（行情总览）** | 四个市场同一张表：最新收盘 / 5·20·60 日涨跌 / 年化波动 / 区间位置 + 对比条 | **直接输地址** —— 站内目前没有入口（见下表后面那条注） |
| **`/portfolio`（组合体检）** | 拿你在「模拟投资」里买的那些持仓算集中度 / 相关矩阵 / 回撤 / 压力测试。取不到的**逐只点名**，行业**不硬塞**，**不算健康总分**（本站没有流动性、成本效率的数据源） | 主页那张卡 |
| **`/ledger`（预测台账）** | 每一次预测落盘、到期拿**真实行情**打分。命中率永远和「无脑喊涨」并排显示，**在线记录和离线回填分开算不混成一个数** | 主页那张卡 |
| `guide.html` | **详细图文版**新手引导（引导页里「详细图文版 →」指向它，仍是纯静态页） | 引导页内链 |
| `graph.html`（辅页面） | **255 词家庭财富管理知识图谱**：每个词一份拆成五栏的解释，一张能点着走的图 | 主页那张「知识图谱」卡，**href 没变** |
| `/legacy` | 换栈之前的那个单页（根目录 `index.html`，**文件没动也没删**） | 迁移期的参照物，见下面「参照物」 |

主页面是**卡式布局**：六张入口卡 + 一张画像卡，功能各自进子页，窄屏自动塌成单列。
主页上**不再**直接放对话卡、K 线卡、Key 卡 —— 它们整体搬去了 `/agent`，一行没改。

> **已知缺口：`/dash` 在站内进不去。** 主页没有它的卡（`HOME_LINKS` 里故意没有，
> 见 `verify_agent.py` 那段注释），引导页第 4 步虽然**提到**「行情总览」，却只给
> `guide.html` 配了链接 —— 所以整个站里没有任何一处能点到它，只能手输地址。
> 这不是设计，是漏了：那段注释写着"它是子页之间的横向入口"，而那个入口**不存在**。
> 补它要动的是引导页（加链接）+ 一条判据 + 一条能打红它的注入，属于下一轮的事。

**八页共用一个壳**（同一份 `web/dist/index.html`）：壳里那个 `#acc-boot` 是
**回测数字的唯一出口**，八页都要用，所以路由只能发生在客户端，不能一人发一份 HTML。

**前端是 React SPA**（Vite + TS + Tailwind v4 + Tremor Raw 组件副本），
`web/dist/` 是**入库的构建产物** —— 所以"不用装东西"这条承诺还在：
跑站的人不需要 npm，只有改前端的人才需要。路由在客户端（`web/src/main.tsx`），
但 `/`、`/agent`、`/onboarding`、`/profile`、`/game`、`/dash`、`/portfolio`、`/ledger` 八条都是**服务端真有的路由**：
直接粘链接、刷新、被搜索引擎抓，三种情况都要落在同一页上。
**没匹配上一律落主页**（`/index.html` 和换栈期的旧链接 `/next` 也是），
不是落 404 —— 一个拼错的地址应该给人主页，而不是一片空白。

**「不用注册、不用登录」这句现在仍然是对的，而且更强了**：画像、引导标记、
游戏持仓全部住在**浏览器自己的 `localStorage`** 里，**服务端零用户状态**——
没有账号、没有会话、没有 cookie，服务端连"谁是谁"这个概念都没有。
下面是三条由此而来的硬纪律，各自的判据都写清楚了。

> **★但「服务端零用户状态」有一个例外，必须写在这里而不是藏在下面某一节里：
> `data/predictions.jsonl`（预测台账）。**
>
> 这是全仓库**唯一**一处服务端为业务写的文件（另一处是 `apikey.write_env` 写 `.env`，
> 那是配置不是业务数据；除此之外无 sqlite、无日志、无会话存储）。它记的是
> **模型自己的输出**——每次预测的标的、`asof`、预测路径、模型指纹——**不含任何
> 用户写的字**：没有提问原文、没有持仓、没有画像，也没有任何能指回"谁问的"的
> 标识（记录里连 IP、UA 都没有）。所以上面那句承诺还站得住：服务端知道的仍然只有
> "这个模型对这只票出过什么预测"，不知道"谁"。
>
> 这条边界**有判据守着，不是一句自我声明**：一条白名单判据逐条检查记录的键
> 只能落在 `_LEDGER_PRED_KEYS` 里，`--selftest` 里配了一条**写入点偷偷多记一个
> 字段**的注入（模拟将来有人顺手写一句 `'question': question` —— 那种改动
> 不会让任何别的判据变红）；页面那一侧另有一条**哨兵判据**：拿一个带哨兵串的
> 问题真发一轮问答，再回读台账，哨兵一个字都不许出现（并配"台账条数必须变多"
> 的对照，否则那一轮压根没写台账，判据是空转的）。
>
> 台账是 **append-only**：只追加、不修改、不删除。到期回填用的是**再追加一条
> `score` 记录**，而不是回头改原来那条——所以"当时的预测"永远查得到原样，
> 这让"事后把预测改对"这件事在文件层面就不可能。代价是文件只增不减，
> 想清空就自己删文件（那是破坏性操作，站里没有这个按钮）。
> 它**入库**（`data/` 不在 `.gitignore` 里），跑站会脏 git 状态；
> `verify_agent.py` 起测试服务时靠 `LICAI_LEDGER` 环境变量把它指到临时目录
> （不这样做的话，每跑一次验证就往入库的那份台账里灌测试数据，
> 而症状是"战绩曲线莫名其妙变难看"，没人会想到是测试写的）。
>
> ★但**光靠环境变量守不住**，这是 2026-09-20 跑完一轮 225 条全红的注入自测
> 之后才发现的：有一条注入专门把 `ledger.path()` 改成无视环境变量、永远返回
> 默认路径 —— 而它的判据组里正好有一枪**真的** `predict_kline`。于是那条
> **用来证明"跑验证不会污染入库台账"的注入，自己成了污染源**：隔离文件 0 条、
> 入库那份多一条，而自测照样报全红（判据确实红了，污染是它的**副作用**，
> 报告里一个字都不提）。查出来的那行是 `600519 / pred_len 8 / lookback 200`，
> 合成行情的指纹，真实预测不可能长这样。
> ⇒ 现在那一组跑的时候，`ledger.DEFAULT_PATH` 被**指到临时目录**：
> 入库那份在代码路径上根本不可达（`path()` 是唯一出口、`DEFAULT_PATH` 是唯一
> 兜底常量，堵这一个点就够）。**不用**"跑前快照、跑完还原"那种写法 ——
> 那个 `finally` 会把同一时刻用户在站上点出来的**真记录**一起删掉，
> 拿删数据的风险换保险不划算。

**它给所有人用，不要求你先是个懂行的人。** 不用注册、不用登录、不用装东西，
不用先学会术语 —— 一个人打开浏览器就能看上图、查上词、跑一次预测。
这句话写在**首屏最上面那条定位条**里（`#siteBanner`，标签就四个字「人人可用」），
不是塞在页脚：页脚那句是免责声明，而定位条管的是"这站我用不用得上"。
判据量的就是它**在折叠线以上**（`bannerTop < 视口高`），并且这段文字里
**真的写清了门槛为零**（不用注册 / 不用装 / 不填 Key 也能用）。

> 定位条**不讲**"本站只做教学"那一套。用户明确否掉过那版说法，所以判据是双向的：
> 新说法「人人可用」必须在、旧说法「只做教学」必须不在 —— 只判前半句的话，
> 谁把它改回去都照样绿。`--selftest` 里为此专门配了一条**回退注入**。

## 怎么跑

```bash
cd /home/ylf/licai-agent
./run.sh                      # 起在 http://127.0.0.1:8848
```

`run.sh` 会先 `unset ALL_PROXY`（本机已知坑：`socks://` 这个 scheme 会弄死 python 侧所有请求），
再用 `.venv/bin/python` 起 `app.py`。

**不用先准备 key，也不用碰命令行**：打开页面，右栏那张「大模型 Key」卡里填上、点保存就行
（下一节）。想先配好再起服务的话，`cp .env.example .env` 手填也照样生效。

**没配 key 也能开**：查词、看图谱、独立预测卡（本地 Kronos）全部照常；
只有对话框需要 key —— 它会给一条结构化提示，告诉你去右栏填，而不是干等。

只想要那张词典图的话，**双击 `graph.html` 就行** —— 单文件、不依赖网络、不需要任何环境。

### 改了前端才需要构建（跑站不需要）

```bash
cd web && npm ci && npm run build     # 产物是扁平的两个文件：dist/app.js + dist/app.css
```

**产物必须扁平**（没有 `assets/xxx-hash.js` 这种带目录的名字），这不是审美：
`app.py` 的 `SPA_ASSETS` 白名单只放行**扁平文件名**，而 `verify_agent.py` 里有一条
**结构性判据**把名单里带 `/` 的条目一律判为可疑形状。加名单的时候有个洞要一起堵：
那条判据原本只读 `WHITELIST`，而 `SPA_ASSETS`/`SPA_PAGES` 是**从另一个目录发文件**的
（`send_from_directory(DIST, name)`，名字里带 `../` 就能指到 dist 外面去）——
**判据已扩到三份名单上**（`WHITELIST` / `SPA_ASSETS` / `SPA_PAGES`），
并配了一条注入（往 `SPA_ASSETS` 里塞 `../.env`，必须变红）。
只守一扇门、旁边那扇连看都没看，是这类白名单最典型的坏法。
`run.sh` 会在产物缺失时当场说清"这是构建产物、不是手写的"，
产物比源码旧时**只警告不自动构建** —— 自动构建会把"改了前端忘了构建"这个失误
悄悄抹掉，而那条判据（`check_dist_fresh`，逐字节比 dist 和重新构建的结果）正是靠它会露出来。

**页面上那句实测数字是会变的**：它由服务端每次请求现读 `kronos_accuracy.json`
（`agent/accuracy.py`）。所以换了模型、改了 `pred_len`/`lookback` 之后要重跑一次

```bash
.venv/bin/python backtest_kronos.py       # 483 个起点，每个一次完整推理（每只标的默认 180 秒上限）
.venv/bin/python verify_agent.py          # 判据会告诉你哪份投影没跟上（页面/README）
```

不重跑也不会"悄悄错"：页面跟着 JSON 走，只有**手抄在 README 里**的那份会红。

## 大模型 Key：在网页里填（`agent/apikey.py`）

右栏那张「大模型 Key」卡就是入口：填进去 → 点保存 → **立刻生效**（不用重启），
状态行会说清"这把 key 是从哪来的"（网页保存 / 环境变量 / 没配）。

**key 仍然只有一个存放处：`.env`。** 网页不是第二个存储，它只是 `.env` 的第二个写入者 ——
`llm.config()` 照旧每次实时读 `os.environ`，**一行没改**。保存时进程内同步更新
`os.environ`，所以不需要重启。

### 优先级只在**这一个键**上翻转

网页填的和 `~/.bashrc` 里的谁说了算？选择是**网页填的说了算**（用户定的），
但这条规则**只对 `DEEPSEEK_API_KEY` 生效**（`WEB_OWNED` 白名单），别的键仍然
`os.environ.setdefault`。这不是洁癖 —— 是 `PORT` 绝不能一起翻：

> 验证脚本靠 `PORT` 环境变量给每个测试服务挑端口。全局翻转的话，每个测试服务都会被
> `.env` 里的 8848 顶掉，**全都去抢同一个口** —— 而"端口上坐着别人"正是本仓库
> 踩过的坑（见下），当时整轮判据都打在别人的进程上，还全绿。

两条边界情况写死在实现里，都有判据守着：

- **空值不算"我说了算"。** `.env` 里 `DEEPSEEK_API_KEY=` 留空**不会**抹掉环境变量里那把 ——
  因为 `.env.example` 里那行本来就是空的，照着"复制一份"走一遍不该把好用的 key 弄没。
  真想清掉，用卡片上的「清除」（它删整行，并把进程内的值还原成"重启后会生效的那把"）。
- **页面和接口都不带完整 key。** `apikey.state()` 结构上就没有完整值，只有 `sk-abc…1234`
  这种掩码；判据把 `/`、`/guide.html`、`/api/status`、`/api/key` 的**全文**扫一遍找完整 key
  —— 只断言"有个 mask 字段"拦不住"顺手把原文也带上"。

写入侧：改 `.env` 是**保留其它行**的逐行合并（不整文件重写），先写 `.tmp` 再 `os.replace`
（原子），落地 `chmod 0600`。

> **CSRF 那条要留个记号。** `<form method=post>` 属于"简单请求"，不发预检，
> CORS 根本拦不住它。真正拦住它的是 `request.get_json(silent=True)`：非 JSON 内容类型
> 返回 `None` → 空 body → 被拒。所以那句 **`or request.form` 千万别顺手加上** ——
> 加了就等于把一个跨站可提交的写 key 接口敞开。

测试隔离：验证脚本用 `LICAI_ENV_FILE` 给每个测试服务一份自己的 `.env`（`env_file_for(port)`），
并用两把**固定的假哨兵**（`KEY_IN_SHELL` / `KEY_IN_FILE`）代替真 key ——
所以整套判据的结果**不取决于跑它的人机器上有没有 key**，渲染层也才有确定的东西可找。

## 智能体是怎么工作的

用户要的是「**小模型 + 大模型**」：Kronos 只负责出预测数字，判断和说人话交给大模型。

```
用户提问
   │
   ▼
DeepSeek（大模型）─ 决定调哪个工具 ─┐
   │                                │
   │   ┌────────────────────────────┘
   │   ▼
   │  get_kline      取历史日 K（akshare，多源降级）
   │  predict_kline  跑 Kronos 小模型出未来 N 根 K 线
   │  search_terms   查 255 词的词典（读现有产物，不联网、不耗算力）
   │  walk_graph     顺「属于/对比/前提」走一步
   │   │
   │   ▼  工具结果**分两条路**回：
   │      摘要（标量，进大模型上下文） + 原始数组（直接发浏览器画图）
   └───┘
   │
   ▼
带方向的回答 + 内联 K 线图 + **强制风险提示**
```

### ★页面上怎么让人看出"这站能预测"（三处标称）

预测是这个站的核心能力，但**之前页面上几乎一个字都没提**：页头徽章只有模型状态和词表大小、
对话卡标题是「问问看」，用户得先问一句走势、再滚下去看见虚线，才知道这里有预测。
补了三处，各管一件事：

| 位置 | 管什么 | 判据盯的是什么 |
|---|---|---|
| 页头 `K线预测` 徽章 | 进站第一眼就知道有这功能 | 它**不许**放进 `#badges` —— 那个盒子每 30 秒被 `status()` 整排 `innerHTML=''` 重建一次 |
| 每条回答的 `⚡ 含小模型预测` 标 | 分得清哪句是模型给的、哪句是大模型说的人话 | 量它的高度；把那行调用删掉必须变红 |
| 主页面顶上的「K线预测」卡 | 不对话也能直接跑：填代码、点按钮、出图 | 卡片里**真的画出了图** + 它**自带风险提示** |

第三处那条路**不经过大模型**，所以那句风险提示没有别人替它说。判据卡的是 `#pout` 里那块
`.disclaim`，不是卡片正文的小字 —— 正文那句"没跑之前"就在，拿它当判据等于**空转**。

第一处还有个坑：探针模式不联网、`status()` 压根不跑，所以"它扛得住重建"这句话
在那个环境下是**测不到**的。现在探针里会先**真的把那排清空一次**再量，
注入也照这个形状打（把徽章挪进 `#badges` → 必须变红）。

**顺带修了布局**：原来写死 `max-width:1180px`，在 2490px 的窗口里内容只占 48%、
两边各空 650px（用户原话"智能体那个页面太小了"）。现在 `clamp(1180px, 78vw, 2200px)`,
大屏两档调字号（≥1700 / ≥2100），**窄屏一行没动**（1400px 那档探针算下来仍是 1180）。
判据盯的是**比例**（主栏 ≥ 视口 70%）而不是某个写死的像素值 —— 写死的话，
下次调宽度就得连判据一起改，**"改代码才能过"的判据等于没判**。

同一个改动顺手带出一个**一直存在但没人看见的错位**：主栏长到 1872px 了，页头那排
`.bar` 还卡在 1180px 上，于是标题和右边那排徽章**整体左移**（大屏实测 20px 起、
徽章那排差出 130px）。修法是让 `.bar` 和 `main` 用同一条 `clamp` + 同样的内边距，
并补一条判据：**量两边的"内容框"**（border box 减去各自左右内边距）左边必须一致 ——
只比 `max-width` 拦不住"内边距一边有一边没有"这种错法。

### 一条关键纪律：工具返回**两条通道**

一次 `predict_kline` 的原始输出是 30×6 个数，加历史尾段 150×6 —— 序列化成 JSON 约 15KB、
约 6000 token，而它承载的信息量（"涨了 3%"）40 个 token 就说完了。更要命的是大模型看一列
裸数字**读不出形状**，多花的 token 纯属噪音；反过来前端没有原始数组就画不出图。

所以 `agent/tools.py` 里每个工具都返回 `{summary, data}`：

- `summary` → 进大模型上下文，只能是标量和小列表，超 4000 字节直接**抛异常**（`assert_compact`）
- `data` → 直接发给浏览器画图，可以是几百根 K 线，**永远不进上下文**

### 模型是什么

**Kronos-small**（24.7M 参数 / 512 上下文），开源金融 K 线基础模型，45 个交易所 120 亿条 K 线预训练。
上游代码 vendored 在 `agent/kronos/`（`UPSTREAM.json` 记了 commit 和三个文件的 sha256）。
权重在 `models/`（`.gitignore` 里，不入库）。

### ★它不能做什么（页面上也是这么写的）

Kronos **只看到了这段价格序列本身**：没有基本面、财报、新闻、政策、资金面。
它的输出是一条**条件采样出来的路径**，不是概率意义上的期望值。
所以本站只给方向 + 风险提示，不给"该不该买"。

### ★实测：模型给的 high/low 有一半不自洽，我们修了它

这条是本轮最要紧的发现，写在这里因为**它改变了"模型输出"这四个字的含义**。

Kronos 把 6 个通道（OHLCV+额）**各自独立**自回归采样，没有任何机制约束
`high ≥ max(open, close)`；上游 `kronos.py:558` 只做 z-score 反归一化就把 DataFrame
返回了 —— **上游根本没有这一步**。所以它吐出来的常常不是一根合法的 K 线。

实测（2026-09-18，RTX 4060 / torch 2.14.0+cu130），10 次独立预测：

| 项 | 实测值 |
|---|---|
| 需要修的 K 线 | **131 / 245 根 = 53%** |
| 最大修正幅度 | 3.84%（相对收盘价量级） |
| 整根翻转（`high < low`）的 | 最多一次 30 根里 5 根 |

所以 `runner._repair_ohlc()` 按 `max/min` 把包络修成合法 K 线，**且修了多少如实报出来**
（`ohlc_repaired_bars` / `ohlc_max_clamp_pct` 进摘要，`caveat` 里写明）。

三条边界，都是刻意的：

- **只动 high/low，绝不碰 open/close** —— 信息在开收价那条路径上，high/low 才是不可靠的那个。
- **顺序是"先修、再断言"**，不能反。`_sanity()` 验的必须是**要发出去的那份**。
- **不悄悄修**。改模型输出这件事必须留痕，而且要在**三条路上同时留**：
  给大模型的摘要（`ohlc_repaired_bars` / `ohlc_max_clamp_pct`）、
  **页面说明条**（"其中 N 根的最高/最低价模型给得不自洽，已按开/收价重建"）、
  以及验证脚本的判据。少一条就等于"悄悄修"—— 只写在摘要里，用户照样看不见。
  `--selftest` 里有**两条**注入分别打前两条路。

> 注意 `_sanity()` 现在的地位已经变了：修正步骤**保证**了它的前置条件，
> 所以它是**备份闸门**，不再是唯一守卫。真正吃劲的部件是 `_repair_ohlc` ——
> 注入要打在它身上（`runner.py` 里那段"要注入的是把 `_sanity(...)` 删掉"的旧注释已按此更正）。

### 推理耗时（实测，不是推算）

`bench_kronos.py` 的真实输出（2026-09-20），机器是 RTX 4060 Laptop：

| | 耗时 |
|---|---|
| 加载权重 | 449 ms |
| `pred_len=10` / `20` / `30` / `60` / `120` | 75 / 138 / 204 / 423 / 893 ms |
| **路径条数=3**（`pred_len=30`，走 `sample_paths`） | 613 ms |
| **路径条数=9**（`pred_len=30`，**线上默认**） | **1890 ms** |
| **每根** | **6.8 ~ 7.5 ms，基本是个常数** |

每根耗时**不随 pred_len 上升**，这从实测上印证了 Kronos **没有 KV cache**：
每生成一根都要把整段上下文重算一遍。也正因为这样，采 N 条就是**乘性**的 N 遍 ——
`路径条数=9` 那一格（1890 ms）≈ `pred_len=30` 那一格（204 ms）× 9，实测就是这个量级。

> ★**这一格以前是"乘出来的，不是量的"**：`sample_paths` 要 N 次**独立**调用
> （`use_cache=False` 是硬要求，理由见下面「分布化输出」一节），而 `bench_kronos.py`
> 原来量的是旧实现（一次调用出 N 条，`sample_count=3`）。旧表里那行 533 ms 是**另一个东西**的数，
> 却被读成"采 3 条要 533ms，那 9 条约 1.6 秒"。现在这一列走的是 `sample_paths` 本身，
> 量出来的就是用户要等的那一下。判据钉着这点：量错了 API，那张表看着一样能用。

**★所以默认 `pred_len` 不是按耗时定的**（120 根也才 0.9 秒，离"用户还愿意等"差着两个数量级，
按耗时挑等于没挑）。它按**预测视野该多长**定：视野越长外推越不可信，保持 30。
`bench_kronos.py` 里那条推荐规则会**如实报告自己没构成约束**，而不是假装给了一个结论。

### ★实测：它到底准不准（这句话是"仅供参考"的兑现）

`backtest_kronos.py` 的真实输出（2026-09-20，4 个市场 / 243 个起点 / 30 根视野，
每步一次完整推理、起点等距取）：

| 口径 | 命中率 | 95% 区间 |
|---|---|---|
| **模型**（预测 30 根之后的方向）的**方向命中率** | **52.3%** | 46.0 – 58.5% |
| 基线一：**无脑喊涨**（衡量"市场本身偏多"贡献了多少） | 50.6% | — |
| 基线二：**跟随趋势**（拿过去 30 根的涨跌当预测，一个真朴素对手） | 45.9% | 39.6 – 52.3% |
| 模型（±0.3% 死区口径 —— 工具层 `direction` 用的就是它） | 49.6% | 43.3 – 55.9% |

收盘价的平均误差（MAPE）：

| | 平均误差 |
|---|---|
| 模型给的路径 | 9.0% |
| **假设不动**（拿今天的收盘价直接当预测） | **4.9%** |

**这张表说的是两件不好听的事：**

1. **方向上的那点优势落在误差范围里。** 52.3% 比无脑喊涨的 50.6% 高 1.7 个百分点，
   但它的区间 [46.0, 58.5] 压着 50%，和基线那条也重叠 ——
   这份回测**没能证明**它在方向上有超额能力。死区口径 49.6%，基本就是抛硬币。
2. **价格水平上它还不如"假设不动"。** 9.0% 对 4.9%，差了一倍 ——
   对"30 根之后收在多少"它没有增加任何信息，反而给出了一条更抖的路径。

> ★**这几个数每重跑一次都会动，而且这是设计的一部分**：`top_p=0.9` 是采样，
> 同一个起点跑两遍给出的是两条不同路径（实测同一批起点两次跑出的路径**逐根不相同**）。
> 更要紧的是**起点个数也会变**：它取决于行情源给回多少根（`feed.fetch` 夹在 1200 根，
> 所以一只约 65 个起点）。所以**跨轮次比这些数没有意义**，只能一轮一轮地看 ——
> 每一轮都指向同一件事，这才是结论。这一轮是 **243 个起点**（上一轮 483 个，
> 样本量本来就不同，别拿两轮的数字互相比）。

那它还剩什么？**形态与波动**：模型给的一步涨跌幅度（1.75%）普遍高于真实的
一步（1.26%），它擅长的是"这段走势的样子"，不是"明天涨还是跌"。
这恰好就是页面上那句话的意思 —— **形态参考，不是涨跌判断**。

分标的一看更清楚（同一个模型，四个市场四个结果）：

| 标的 | 模型 | 无脑喊涨 | 跟随趋势 | 这段里实际上涨的日子 |
|---|---|---|---|---|
| 贵州茅台 | 60.0% | 43.1% | 38.7% | 43.1% |
| 比特币 | 54.2% | 52.1% | 48.9% | 52.1% |
| 腾讯控股 | 49.2% | 50.8% | 44.3% | 50.8% |
| 苹果 | 46.2% | **56.9%** | 52.4% | 56.9% |

- 茅台那 60.0% 看着最漂亮，但同期**跟随趋势只有 38.7%** —— 说明那段行情是强均值回归，
  模型"猜反转"正好猜对了。这不等于它会猜反转。
- 苹果那格是反过来的：模型 46.2%，而**无脑喊涨就有 56.9%** —— 它跑输了一个哑巴。
- 所以一个标的的数字不是结论。**四个标的分不出稳定的胜负，这才是结论。**

三条写进脚本里的规矩（少一条这张表就不能信）：

1. **必须有对等基线**：命中率单独看会骗人 —— 窗口里若有 60% 的日子在涨，
   无脑喊涨就有 60% 命中率。所以并排报三条。
2. **不许挑窗口**：起点按固定步长等距取、覆盖整段历史，跑多难看都照报。
3. **方向要带死区**：预测 +0.05% 和实际 +0.05% 撞上纯属巧合，所以两套口径都报。

> **难看本身就是"只做参考"的证据。** 把"仅供参考"四个字换成这张表，用户才知道该信几分；
> 留在四个字上，它写在哪儿都不担责任。
> 页面上的那句实测（以及 README 里这些数）由 `verify_agent.py` 钉在
> `kronos_accuracy.json` 上，其中一条是**对照**：换掉 JSON 里的数，页面必须跟着变 ——
> 换不动就说明那句话是写死的。手抄进 HTML 也能"今天看着完全正确"，但那种正确活不过下次重跑。

## 主页那一层：六张卡 / 引导 / 画像 / 模拟投资

主页从"对话式智能体"变成了**导航层**：六张入口卡把功能分到各自子页，外加一张
「我的画像」回显卡。这一层有四件事值得写下来，因为它们的**坏法都是静默的**。

### ① 引导只自动出现一次，靠的是 `localStorage`，而在探针下**必须不跳**

「第一次来就送去新手引导」这半句，写起来是 `location.replace("/onboarding")`。
它有一个非常难看的坏法：`replace` 会**把 `?probe=1` 一起丢掉** ——
于是落在 `/onboarding` 上的探针根本不会 beacon，几十条渲染层判据集体变成
「没收到探针数据」。**"跳到 /onboarding"和"整页白掉"在报告里长得一模一样**。

所以这一段有**两条各自独立的判据**，缺一条就守不住：

| 判据 | 守什么 |
|---|---|
| `shouldAutoOpenOnboarding()` 的真值表（纯函数，`run='mod'` 直调） | 判断**本身**对不对 |
| 探针载荷里的 `bootPath` 必须还是 `/` | 那个判断**被谁调用了**、有没有把探针一起跳走 |

**函数写对了、调用点漏了那半条保命线，第一条照样绿。** 这类"判据测的是纯函数、
用户走的是调用点"的分叉，本仓库踩过不止一次。

> 同一段代码里还有一条**顺序**上的要求：探针那条保命线必须排在自动跳转**之前**。
> 顺序反了的表现和"没写"完全一样（都是没数据），所以它也得靠上面那条 `bootPath` 抓。

### ② 画像只在浏览器里，而它进的是**提示词**，不是工具

画像（兴趣 / 风险偏好 / 资产区间 / 收入区间）由前端放进 `/api/chat` 的 body，
`llm.build_messages(..., profile=...)` 现拼进 system prompt。

**它不是一条工具。** 工具表（`REGISTRY` / `SCHEMAS`）一行没动 ——
一个"能读你资产"的工具和一段"写在提示词里的自述"，在出错的后果上不是一回事。
判据走 `run='mod'` 直调 `build_messages`：带画像时 `messages[0]` 里必须**有**那几个字段，
不带时**必须没有**（后者是对照组，缺了它"拼没拼"根本测不出来）。

### ③ 模拟投资：**抓不到行情就明确报错，绝不编数字**

这是用户点名的一条，也是最容易被"顺手返回 0"破坏的一条。

- **失败响应里一个收益数字都不许有。** `agent/game.py` 的 `_fail()` 是**唯一**的失败出口，
  键**恰好**是 `{ok, error, msg, hint}` 四个、`data` 是 `None`。
  判据就是照着这个形状写的：多一个 `pnl_pct: 0` 那种"方便字段"，就会有一个
  用户会当真的数字（"我没赚没赔"），而真实情况是**我们不知道**。
- **HTTP 状态码本身也是一条判据的落点**：失败是 **400**，不是"200 但里面写着 `ok:false`"。
  后者在只看状态码的地方看起来一切正常。
- **买入日与买入价要独立推一次。** 第一版判据只验了"买入价 == 所报那天的收盘价"——
  这是**自洽**的，一次把两个一起挪的注入（把"回看"悄悄变成"用最后一根日 K"）
  能让它**照样绿**，而页面上"回看三个月"变成一个永远是 0 的盈亏。
  现在的判据拿 `/api/kline` **独立算一遍那天是哪天**，两个数必须同时对得上。
- **虚拟本金与画像里的资产无关**（用户的明确要求，判据也是两条）：
  给一个画像里写着"100 万以上"的请求，本金框必须是**空的**。
  ★这条判据有个**空转**风险：没有画像时本金框当然也是空的，坏成什么样都绿 ——
  所以探针必须在 `flushSync` 渲染**之前**把画像播进去（本金框的值是挂载时读一次的），
  判据里也把"同一时刻画像里的资产"一起报出来当对照组。
- 一局的本金上下限（100 ~ 1 亿）**不是风控**，是挡住手滑多打几个 0；超了就明确报错，不是截断。
  `bool` 和 `nan`/`inf` 要单独挡（`isinstance(True, int)` 是 `True`，不挡的话 `{"amount": true}`
  会变成 1 元本金悄没声地跑通）。
- **推荐只是推荐**：按兴趣给一份清单，但输入框照样能搜任意标的。判据专门挑一个
  **不在推荐列表里**的标的，它必须照样报得出价。
  ★挑哪个"别的标的"本身有讲究：第一版挑了一个**我自己在桩里故意让它失败**的代码，
  判据红得与它要测的东西毫无关系；改成白名单里存在的一个之后，注入反而**打不中**了
  （因为它就在池子里，被注入的白名单接受了）。现在用的是 `AAPL`。
- 取不到的类别（银行理财 / 存款 / 保险 / 外汇）**明说自己取不到**，
  不拿别的类别硬凑一只充数 —— 给一个选了"存款"的人推一只股票，等于告诉他"存款就是这个"。

### ④ 七页共用的东西，判据得在**每一页**都量

`SiteBanner`（定位条）和圈状波纹都是 `main.tsx` 里一次装上的、七页共用。
只在一页上判的话，"某页把它摘了"不会被发现。所以定位条那三条和波纹前三条
**在主页和 `/agent` 各判一次**。

圈状波纹本身有一条值得一提的纪律：**它待在 `<body>` 上、`position: fixed`、
`pointer-events: none`**，不挂进被点的元素里。挂进去就得给那个元素（或它的某个祖先）
动态加 `position: relative` + `overflow: hidden`，而那会改变**层叠上下文**，
表现是"某个下拉菜单突然被裁掉了"这类极难查的问题。
判据里有两条是照着这个决定写的：**点击前后被点元素的 `getBoundingClientRect()` 逐像素相同**
（四个方向都要 0）、以及 `pointer-events` 必须是 `none` ——
它是个 190×190、`z-index: 9999` 的圆，设成 `auto` 就是一块跟着点击点出现的**遮罩**，
而页面上看起来只是多了个圈。

> **这条判据的注入写错过一次，值得记**：第一版把 `HOSTSEL`（"哪些元素该冒圈"）
> 窄成 `".card"`，理由是"选项卡不在 `.card` 里"。**这句是错的**：`closest` 是
> **从被点元素往上找**，而两页的选项卡都在一张 `.card` 里面（`/profile` 在
> `<section id="profileFormCard">` 里，`/onboarding` 那一步的 `{STEPS[i].body}`
> 渲染在 `<section id="obCard">` 里），往上走一层就命中那张卡，圈照冒。
> 自测报 `no-red`，**报出来的样子是"这条判据是装饰"，真正错的是注入** ——
> 它造了一个对选项卡没有区别的状态。现在改成窄成 `"a"`（主页那六张卡是
> `<a class="card linkcard">`，照样命中 ⇒ 三条卡片判据全绿，只有选项卡那条红）。

### ⑤ 分位条不能用涨跌色（这条是**真的**曾经错上线过）

A 股是**红涨绿跌**（和欧美相反），颜色只从 token 来，不散落在组件里。
而浅色主题的 `--accent` 与 `--down` 曾经是**逐字节相同的 `#1b6b4c`** ——
于是"这只票的 PE 在近 5 年偏低的档位"被画成了**下跌的颜色**，用户扫一眼会读成"它在跌"。
分位只是"跟它自己过去比站在哪"，**不是涨跌**。

修法是给 `.fbar-fill` 一个中性色（`--ink-3`），判据一个字没改。
对应的注入用的是 `var(--down)` 而不是 `var(--up)`：**照真实发生过的形状注入**，
将来有人把 `--accent` 挪回来时，它会照着同一个方向变红。

两个设计点：

- **粘性记忆**：记住上次成功的源并优先用它。东财在本机是"时通时不通"，一个挂掉的源要走完
  urllib3 的重试才失败（实测 2 秒级）。但**失败时仍然全链都试**，所以这只是省时间，
  不会把"源恢复了"挡在外面。
- **有歧义就反问，不替用户选**：`000001` 是上证指数还是平安银行，差得远 ——
  猜错了整段分析都是错的，所以工具直接抛 `AMBIGUOUS` 让大模型回去问。

## 组合体检（`/portfolio`）：不预测，算能算的

预测那条路已经自证走不通（见上面「★实测：它到底准不准」）。这一页换了一层：
**不碰 alpha，只算持仓本身的形状** —— 集中度、相关矩阵、回撤、压力测试。
这些结论**不需要超额能力也成立**，而且每一个数都能独立复算。

**持仓不新建第二套模型**：读的就是模拟投资那个 `localStorage` 键，`amount` 归一化成权重。
你在游戏页买的每一笔就是你的组合，叙事上连得起来。

### 三条不变量（违反任何一条就是把这站最值钱的东西拆掉）

**① 数字必须由代码算，大模型只负责解读。**
`skills/` 里那两个技能是**纯文本框架**（阈值表 + 报告模板）。直接塞进提示词而不给数据，
等于让大模型**拿着持仓眼估**集中度 —— 那正是 `game._fail()` 拼命在防的事。
所以分工切开了：skill 给阈值和框架，`agent/portfolio.py` 算每一个数。
框架文本进提示词走 `agent/skills.py`，而且**一条阈值都不许有**（阈值住在别处，
有一条判据双向钉着它，注入就是"把阈值漏进提示词"）。

**② 表与文必须两层一致。**
阈值同时活在 `skills/portfolio-health-check/references/diagnostic-framework.md`
和 `agent/portfolio_rules.py` 里。改一处另一处不动的症状是"代码判红灯的档位和文档写的不一样"，
所以判据是**双向**的（md 表 ⟺ 常量，两边都要查）。和词表那条"对比边 ⟺ 辨析栏"同一个形状。

**③ 算不出来就说算不出来，不给"方便字段"。**
本条直接决定了报告的形态：**不算健康总分**。skill 的模板里有 7 个维度加权成 0–100，
其中「流动性」「成本效率」本站**没有任何数据源** —— 给一个含这两项的分数，
等于用一个编出来的数字去稀释六个真的。页面上的原话就是这么写的。

### 失败纪律（这一页的重点）

- **逐条降级、并且点名**：某只取不到 → 明确列出"这几只没取到、已从计算中排除"。
  静默丢掉一只 = **悄悄改变了组合的集中度**，而页面上看不出少了谁。
- **样本不足要说**：只有一只持仓时相关性/EDR 在数学上无意义，明说"谈不上分散"，
  不给一个 HHI=1 的红灯当结论。
- **行业不许硬塞**：ETF/指数没有公司概况里的行业，那就说"没有硬塞进任何一个行业"，
  不塞进"其他"充数。
- **残缺到一定程度就拒出报告**：活下来的权重低于 60% 直接说做不了，
  而不是拿残骸算一份看着完整的报告。

### 页面那一屏也要有判据 —— "算得对"和"画出来了"是两件事

`check_portfolio_calc` 判的是**数算得对不对**，全在进程内直调。
算得对而页面上没画出来（或者画成了别的），它一条都不会红 ——
这正是本仓库那条「读产物不读输入」要防的形状：**算出来的数**是输入，
**用户在屏幕上看到的那一屏**才是产物。

所以 `check_portfolio_page` 再判一遍**只有这一页才有**的东西：

| 判据 | 为什么 calc 那侧抓不住它 |
|---|---|
| 失败时接口回 **400**、`summary` 只有四个键、`data` 是 `None` | 状态码是一条判据的落点；"200 但里面写着 ok:false"在只看状态码的地方一切正常 |
| 页面列的就是接口算出来的那几只（**逐字比代码**） | 只比行数的话，"把取不到的那只也列进来"两边一起多，照样绿 |
| 页面上那几个数就是接口给的数（逐字段） | 六项里写死一项，其余五项照旧对 —— 只判"这块渲染出来了没有"是瞎的 |
| 取不到的那只**点名**了（量高度） | calc 那侧判的是 `dropped` 列表非空，而**画不画**是另一回事 |
| 相关矩阵的底色是**中性色** | 用 `--up` 涂色时所有数都对、矩阵也真画出来了，唯一的问题是"高相关"看起来像"跌了"（这条真的上过线，见 ④） |
| 算不了的那一屏**没有任何指标块** | 显示 0 会被读成"算出来是 0" |

★**判据量的是高度（`getBoundingClientRect`），不是"这几个 id 在不在 DOM 里"** ——
藏起来的元素 `textContent` 照样返回全文。

### 图表不用任何图表库

相关矩阵是 **CSS grid + 背景色块**，权重条是 `div` 宽度，净值曲线是**内联 SVG**。
理由不是省体积：这是整个换栈过程中反复踩到的 —— **Tremor 的 `ResponsiveContainer`
靠 ResizeObserver，同步量到的是 `0×0`**，而探针在**同一个 tick** 里量几何。
Recharts 的首帧尺寸探针量不到（`/dash` 的对比条因此也是手写 `div`）。
引入图表库 = 这一页的渲染判据**集体消失**，而"消失"在报告里长得像"页面坏了"。

### 这一页踩到的坑

> **桩的日线给少了，判据会"永远红"，而它看起来像"页面坏了"**：
> 相关矩阵要 `MIN_WEEKS = 52` 个周收益点才算得出来，而 `_dash_stub` 默认只给
> 250 根日线（≈50 周）。于是 `corr` 恒为 `None`、`#pfCorr` 整块不渲染 ——
> 判据红在"这块没画出来"上，而**块本来就不该画**。一条永远红的判据和永远绿的一样没用，
> 它只是把真信号淹掉。⇒ 这一页的桩一律传 `days=800`。

> **拿页面上那几只回打接口 = 拿 A 比 B**：页面上那三只已经是被筛过一遍的结果，
> 用它回打就验不到"取不到的那只混进来没有"—— 而那正是那条判据要守的。
> 判据必须拿**探针种下去的那四笔**（和前端 `probeSeedPortfolio()` 同一份）打，
> 而且要额外断言 `dropped == ['600519']`。**产物只能出现在被比的那一侧，不能出现在输入那一侧。**

> **★★一条空转了很久的判据，和它盖住的那个真 bug**（这一轮最值得记的一条）：
>
> `check_portfolio_rules` 里那半条「只有一只持仓时不许出现任何『分散…』的档位」，
> 输入是**手搓的 dict**，而那份 dict **漏了 `edr` 键**。`grade()` 的约定是
> "缺的键 = 这项算不了" —— 缺 `edr` 就**压根不产出 EDR 那一行**，于是
> `any('分散' in r['level'])` **一次都没可能命中**。它绿了很久，而且是"合法地"绿：
> 循环跑过了、断言执行了、只是那个集合永远是空的。
>
> 真跑一次单只持仓才看见：`grade()` 实得 `有效分散比率（EDR）｜几乎无分散效果`。
> 而单只时 **EDR 恒等于 1**（Σσ 就是它自己那一个 σ，组合就是它本身）——
> 那是**恒等式，不是一次测量**。拿它报最坏那一档，等于用一个编出来的结论去稀释真的，
> 和「不算健康总分」是同一条纪律。⇒ `portfolio_rules` 里那条 `n < 2` 的闸门
> **从来没写**，而本该拦住它的判据一直是绿的。
>
> 三条教训，每条都改了做法：
> 1. **断言"不该出现什么"的判据，输入必须是完整的。** 断言"该出现什么"的缺键无所谓
>    （它本来就在测某一档的边界，实测那五条边界判据一个字都不用改）；
>    但凡判据是"这里**不许**有 X"，缺一个键就等于把 X 从视野里删掉。
> 2. **手搓输入会和真实产物悄悄漂开，所以修法不是"把键补全"就完事** ——
>    补全只是把这一次的洞堵上。真正拦得住这一类的是**再配一条走 `analyze()` 真产物**的
>    判据（`★单只持仓：EDR 不许拿恒等式 1.0 当…`），因为只有真产物知道真产物长什么样。
> 3. **注入得半条对半条。** 原来那条注入（⑮）只打"相关性聚集"那半边，
>    "分散"那半边**一直没有注入** —— 于是一条永远不会红的判据，谁也没机会发现它空转。
>    现在两半各有各的注入。
>
> 一句话：`--selftest` **只遍历注入、不遍历判据**，所以"没有注入的判据"它不会替你报错。
> 一条判据里塞了两个断言时，一个注入只覆盖得住一半。

## 预测台账（`/ledger`）：把"它准不准"变成一条会自己更新的曲线

前面的回测已经给出硬结论：**单序列预测没有超额能力**（方向 52.3% vs 无脑喊涨 50.6%）。
台账不是来翻案的，它的作用是让这个结论**不必靠人再跑一次回测**——每一条真预测
落盘、到期拿真实行情打分，页面上的战绩随站自己长。这也是全站唯一一处
**服务端为业务落盘**的地方，边界见前面那段引用块。

### 落盘格式：事件日志，只追加

`data/predictions.jsonl`，一行一个 JSON，三种记录：

| `kind` | 什么时候写 | 带什么 |
|---|---|---|
| `pred` | 每次真预测 | 标的 / `asof`（站在哪根上）/ `pred_len` / 方向 / 预测路径 / 区间 / 模型指纹 / 输入被修过几根 |
| `score` | 到期回填时**再追加一条** | 指向 `pred` 的 `id` + 那几根**真实收盘价** |
| `skip` | 判定**永远**算不了时 | 指向 `id` + 为什么 |

**当前状态 = 把这几条记录 fold 一遍**（`ledger.state()`）。没有"改一条记录"这个操作，
所以"事后把预测改对"在文件层面就不可能——想改只能改历史文件，那是另一个性质的事。
幂等靠 `pending()` 排除已有 `score`/`skip` 的记录；冷启动导入的 id 由内容算出来
（`bf-<代码>-<asof>-<根数>`），所以重跑一次回测不会让台账翻倍。

### ★记的是**打分的输入**，不是分数

`score` 记录里存的是那几根真实收盘价，**不是**命中/没命中。分数在**读的时候**才由
`agent/score.py` 算（`outcome_row()`）。

这一条是整个设计里最值钱的地方：哪天打分口径改了（死区宽度、方向怎么算），
**整份历史会一起跟着改**，而不是留下两套口径在新旧记录里打架。存分数就做不到了——
旧记录是按旧口径算的，而且没人看得出哪些是旧的。

`agent/score.py` 是**唯一**的打分出口，离线回测（`backtest_kronos.py`）和在线台账
共用它。理由和"数字只有一个出口"是同一条：不共用的话，"回测 52.3%"和"页面台账 60%"
会同时挂在站上，**而且没人看得出哪个是对的**——两个数都是"算出来的"。

### 回填：到期了才打分，算不了要说清楚

到期判据是"`asof` 之后**已经有 `pred_len` 根真实 bar**"，取的就是严格在 `asof`
之后的前 N 根——**和离线回测同一把尺子**。不够 N 根给 `None`（不是"有几根给几根"，
那会把一个 3 根的窗口当成 8 根的预测来打分）。触发是惰性的：请求时按需回填
（`/api/ledger` 要显式带 `refresh=1`，默认**不回填**，否则每次刷页都在写盘），
加上启动时一个后台线程（`LICAI_LEDGER_NOBOOT=1` 关掉，测试服务用它）。

**三个计数是分开的，绝不能合成一个**：

| 计数 | 含义 | 是好事还是坏事 |
|---|---|---|
| 还没到期 | 正常在路上 | 正常 |
| 永远算不了（`skip`） | **已判定**：行情窗口根本覆盖不到它的起点 | 一次决定，不再重试 |
| 到期了但路径对不上（`skipped`） | 该能算却算不了 | **这是坏的**，要有人去看 |

**"取不到行情"故意不记 `skip`**：那是暂时的（源站抽风、断网），下次还要重试。
把它记成"永远算不了"，等于一次网络抖动就永久放弃一条记录。
两条判据分守这两侧，各配一条注入。

### 页面：两个分区，命中率永远配着基线

**在线记录（`live`）和冷启动回填（`backfill`）分区显示，绝不混成一个数。**
冷启动会把 `backtest_kronos.py` 那些滚动窗口也写成台账条目，几百条离线窗口一混进来，
"台账战绩"就几乎全由它们决定了——而它看起来像是这个站在线跑出来的成绩。
这是这一页最不能犯的错，所以有一条判据专门钉"两个分区各是一块"+一条注入
把两块合成一块打红。

每一块的命中率**并排显示"无脑喊涨"基线**，而且判据要求两者**不相等**——
只判"基线在不在"的话，把基线写成命中率复制一份照样绿，而那份基线一个信息量都没有。

**区间覆盖率那一栏，算不出来就一个数字都不给 —— 而且理由由服务端给。** 记录里的
`interval_kind` 分得出"这是哪种区间"：单次采样那条路径的 min/max 是**路径极差，不是置信区间**，
拿它算覆盖率量的是"模型这几根走得飘不飘"，不是"80% 区间覆没覆盖住"。
多采样分位数（阶段 3）才是。这和"不给健康总分"是同一条纪律：
**算不出来就说算不出来，不给一个看着像结论的数**。

> ★那一栏的理由**不写在页面里**，它是 `ledger.coverage()` 的 `why` 回的。这不只是省事：
> 写在页面上的理由是**第二处真源**，而且它会**静默变成假话** —— 原来那版写的是
> 「还没校准，不给数字」，等离线校准（`backtest_kronos.py --coverage`）真跑完之后，
> 那句话就不成立了，而它跟真的理由**长得一模一样**，从页面上看不出哪句过期了。
> `why` 分得出两种情况（台账里根本没有多采样区间 / 有区间但一条都没到期），
> 它是唯一知道当前是哪一种的地方。判据因此比的不是"页面上有没有『不给数字』四个字"
> （硬写一句就能满足），而是**页面那一栏里有没有服务端那句 `why`**。

页面还把**台账文件路径**印出来（`#lgWhere`）——往磁盘写了什么，得让人看得见。

## 分布化输出与目标推演（阶段 3）：把"没有超额能力"变成产品行为

前面「★实测：它到底准不准」那个结论是硬的：**单序列点预测没有超额能力**
（方向 52.3% vs 无脑喊涨 50.6%、MAPE 9.0% vs 假设不动 4.9%）。
所以这一层的价值不能在"把预测做得更准"上找，只能**换层**：从「一个数」换成
「一个区间 + 一个概率」—— 这两样**不需要 alpha 也成立**，而且都能独立复算。

### ① `predict_kline` 默认出 **N 条**采样路径（`DEFAULT_SAMPLES = 9`）

默认值**不是 1**，9 也不是随手挑的：

- 区间是 N 条**独立**路径的极差 `[min, max]`。一个新样本落进这个极差的概率有精确公式
  **(N−1)/(N+1)** —— 它不用对分布做任何假设（顺序统计量的性质）。
  N=9 ⇒ 正好 **80.0%**。所以"名义 80% 区间"里那个 80% 是**定义出来的**，不是估出来的。
- N 条必须是 **N 次独立调用**：`use_cache=False` 是硬要求。缓存键里**没有采样序号**，
  开着缓存取 9 次会拿到**同一条**路径 —— 那样极差是 0，页面显示"区间宽度 0%"，
  看着像"模型非常确定"。
- `DEFAULT_SAMPLES` / `MAX_SAMPLES` / schema 说明里那个数**三处必须一致**，判据钉着
  （改一处漏另一处，大模型读到的工具说明就和实际行为对不上）。

### ② 弃答：模型没一致看法，就说没一致看法

`spread.withheld = true` ⇒ **方向弃答**。判据是 N 条路径的投票比例、其 **Wilson 95%
区间跨过了 50%** —— 问的是"这些路径系统性地偏向一边吗"。弃答时 `direction` 是 `flat`，
摘要里明写"模型在这只上没有一致看法"，**不给方向也不给区间**。

这是**特性不是缺陷**：把已测出来的"没有超额能力"直接变成产品行为，而不是硬给一个
方向再配一句免责声明。规则自带一条可查的性质：**N 越大区间越窄 ⇒ 采样越多越容易
给出方向**（N=9 时要 8/9 或 9/9 才给），想少弃答就多采样。

> 曾经有一版判据是"区间跨过基准价就弃答"，已废弃：实测 6 个起点真/假各半，
> 而它反映的其实是"模型把中心挪了多远"（同批起点中心线从 −8.8% 到 +14.1%），
> **不是**"模型有没有一致看法"。拿一个在量别的东西的条件当判据，
> 症状是弃答率看着正常、含义是错的。

### ③ 覆盖率：**没量过之前，页面一个数字都不许写**（现在量过了，下面就是量出来的）

`backtest_kronos.py --coverage` 在**每一个起点**上多跑 9 次**独立**采样，
把"名义 80% 的区间到底覆盖住了多少"量出来。实测（2026-09-20，243 个起点）：

| | 名义 | 实测覆盖 | 95% 区间 | 宽度中位数 |
|---|---|---|---|---|
| **模型的 9 条采样路径** | 80% | **28.0%**（68/243） | 22.7 – 33.9% | **10.97%** |
| 对照：**不用模型**的波动带（日波动率×√h×1.2816） | 80% | 84.8%（206/243） | 79.7 – 88.7% | 27.07% |

**结论是从置信区间读的，不是从"差了 52 个百分点"读的**：实测的**上界 33.9% 都够不到
名义的 80%** ⇒ 这个区间**系统性偏窄**，名义水平是乐观的。同一个起点上，不用模型那条
带子（同样的名义 80%）覆盖 84.8%、区间跨着 80 —— 它是**站得住**的，而它比模型的带子
**宽 2.5 倍**。

所以这一层真正说的话是一句不太好听的：**"80%"不是这个区间的性质，是它想要的水平。**
模型给自己的不确定性**太小**了 —— 它选出了一个 10.97% 宽的带子，而历史上真实发生的
波动需要 27% 那么宽。这跟前面"方向没有超额能力"是同一件事的两面：
**它不知道自己不知道什么**。

分标的（同一件事在四个市场都成立，程度不同）：

| 标的 | 名义 | 实测覆盖 | 宽度中位数 | 对照波动带覆盖 |
|---|---|---|---|---|
| 贵州茅台 | 80% | 49.2% | 6.29% | 92.3% |
| 苹果 | 80% | 26.2% | 11.43% | 83.1% |
| 比特币 | 80% | 18.8% | 13.88% | 75.0% |
| 腾讯控股 | 80% | 15.4% | 12.46% | 86.2% |

**判决写在页面上，而且是"连在一起"写的。** 那句实测数字的末尾会跟一句
「区间校准：名义 80% 的多采样区间，实测覆盖 28.0%（243 个起点，95% 区间 22.7–33.9%，
中位宽度 10.97%）；同样名义的纯波动率区间覆盖 84.8% ⇒ 实测覆盖率的上界都够不到名义值，
说明模型给自己的区间偏窄」。**"名义 80%"这几个字不许单独挂在页面上** ——
`backtest_kronos.py` 在实测上界低于名义时会直接这么要求，而 `agent/accuracy.py`
里那个 `coverage()` 是**结构上**保证它的：那一句要么整句在、要么整句不在。

几条钉住它的规矩：

- `ledger.coverage()` **只认** `interval_kind == 'sample_quantile'` 的条目 ——
  单次采样那条路径的 min/max **不是区间**，拿它算覆盖率是在量别的东西。
- 口径是**终点**（`actual_close[-1]`），与 `interval_level` 的名义含义对齐；
  按"每一根"算会把数系统性抬高（早期几根离基准价近）。
- ★**名义值必须由采样条数现算出来**：`nominal_pct == score.level_of(N)`，
  而 `N` 必须是**线上真发的那一个**（`tools.DEFAULT_SAMPLES == backtest_kronos.COVER_SAMPLES`，
  JSON 里那份 `n_paths` / `config.coverage_samples` 也要等于它）。改了默认采样条数
  而不重跑校准，那句"名义 80%"就**不再是这个区间的东西** —— 而页面上那个数看着一模一样。
  判据把这三处钉在一起，配了五条注入（改 `tools.py`、改 `backtest_kronos.py`、
  改 JSON 里的 `n_paths` / `nominal_pct` / `zero_width`）。
- ★**"量过才准出现"是两个方向都查的**：给 JSON 一块 coverage → 页面上必须出现那几个数；
  把它摘掉 → 页面上**一个字都不许提覆盖率**。只查后一半的话，把那一句写成"恒不出现"
  也照样绿 —— 而那恰恰是"校准跑完了、页面没接上"最可能的样子。
- ★那条**缓存哨兵**：`sample_paths` 的 `use_cache=False` 一旦被去掉，N 条路径会变成
  同一条，区间宽度全 0 ⇒ 覆盖率会变得"看起来刚好"或"完全不够"，而根因根本不在校准上。
  脚本碰到它就**拒绝写 JSON**（实测 `zero_width = 0`），判据再守一道。

和 `accuracy.py` 那条"要么连基线一起给，要么整句不给"是同一条纪律。
**唯一的例外是 `/ledger` 那一栏**：它算的是**这个站自己发过的**（在线）区间，
和上面这份离线校准是两回事 —— 台账里还没有到期的多采样区间时，它照实写"算不出来"
和理由（理由由服务端给，见上面台账那节）。

### ④ 目标达成概率（`agent/goal.py`）：分布来自**历史重排**，不是模型

问"每月投这些、放这么久，攒到某金额的概率"要的是一条 60 个月的价格路径。
**不能**拿 Kronos 撑：它在 30 天视野上都没赢过"不动"，把它外推到 60 个月，
得到的是一个**看着最像结论、却一点依据都没有**的数。

⇒ 换一把尺子：**把历史上真实发生过的那些月份重排一遍**（moving block bootstrap，
12 个月一段、**不环绕**）。它不预测未来，给的是"在曾真实出现过的波动结构下，
这件事的概率大概是多少"。

三条硬规矩，每条都配判据：

| 规矩 | 不守会怎样 |
|---|---|
| **档位绝不取中点** | 「20-50万」「3000-1万」是用户选的**区间**，取中点 = 替他编一个他没说过的数（"100万以上"连中点都没有）。⇒ 两端各算一次、当区间报；不封顶的只给**单边下界**并写明是下界。 |
| **同一个问题永远同一个答案** | 种子由 `(标的, 月数)` 推出来（`zlib.crc32`，不用内置 `hash()`：它对 str 每进程加盐）。★种子**不含月投入** ⇒ 同一期限下"投得多"在**每一条路径**上都成立，而不是两次抽样之间的噪声。 |
| **太短就说太短** | `feed.fetch` 上限约 57 个月收益，`MIN_MONTHS = 36` 以下不算。★**只有一道闸**（第一版有两道，注入只拆得掉一道 ⇒ 那条注入就成了装饰）。 |

**"分布必须来自历史重排"这条判据配的注入是"改用 Kronos 路径"，而且拆成两条**
—— 一条守不到另一条：

1. **产物层面**：每条路径都能**拆回历史上的连续段**（贪心匹配、段数 ≤ ceil(月数/段长)）。
   ★两个对照组是这条判据的一半：同均值方差的正态抽样、把历史值**打乱**重抽 ——
   后者每一位都还在历史里，只有"相邻"这条没了。实测：真重排 3 段，正态拆不动，
   打乱 34~36 段。没有对照组，"值都在历史里"就够骗过这条判据。
2. **引擎层面**：**把模型那条路整个堵死，照样算得出来**。产物那条看不见"在 `plan`
   层绕过重排"的写法，这条看不见"在 `sample_paths` 层绕过"的写法。

> **假设必须跟着数字走。** 摘要里那段 `caveat` 是发给大模型的**强制清单**：
> 重排不是预测（历史分布 ≠ 未来分布）、推的是沪深300的历史**不是他手里那个组合**、
> 两端一对没有中点、敏感性那几格是**假设**年化下的确定性推演、不许说"一定能达成"、
> 不许说该买什么。判据查的是它**逐条点名**（7 条），不是"非空"——
> 一句"仅供参考，投资有风险"就能过"非空"，而它一个真信息都没带。
> ★这条不是文案：删掉它，页面上剩下的就是一个光秃秃的"62%"，而那个数没有依据。
> （配的注入就是把整段 caveat 换成那句通用免责声明 —— 锚点是**整段** 13 行，
> 只换其中一句的话剩下几句照样拼在后面、关键词还在，判据不会红。）

## 换前端这一轮（React + Tremor）：判据是**加强**，不是换一套

视觉目标（"要有金融的感觉"）是换栈的理由，但换栈最容易顺手做的一件事是
**把判据换成一套顺着新代码写的**。所以这一轮全程守住三条，每条都有代价、都有判据：

### ① 数字仍然只有一个出口

SPA 壳里放的是 `<div id="acc-boot" hidden><!--ACCURACY--></div>`，服务端照旧每次请求
现读 `kronos_accuracy.json` 填进去，React 只负责把它**搬进可见节点**，
`#disclaim .acc-line` 这个 id/class 原样保留。

`page()` 这一轮**只加了一个 `base` 参数**（壳子从 `web/dist` 发），填数字那段
`accuracy.fill(f.read())` **一个字符没动** —— 而且 SPA 壳仍走**同一个** `page()`、
同一个 `/` 入口，没有另开第二个数字出口。

⇒ 于是"换掉 JSON、页面必须跟着变"那条对照**照旧成立**，而且多了一条新形状要防：
**壳里有数字 ≠ 用户看得见**。所以渲染层那条判据量的是 `#disclaim .acc-line` 的**高度**，
并且专门配了一条注入：把 React 里读 `acc-boot` 那一步删掉 —— 必须打红**渲染层**，
只打红源码层不算数（源码里数字还在，用户看不见，这正是最像"绿"的那种坏）。

### ② 探针必须还是**同步**的，这不是风格问题

渲染层判据全部押在"页面把几何在**同一个 tick** 里量好送回来"上。换 Recharts 时先做了
一个 go/no-go 的 spike（同一份数据、同一个固定像素的父容器，两条路径各量一次）：

| 时刻 | 裸 `ResponsiveContainer` | 定尺寸分支 |
|---|---|---|
| **t0 同步（flushSync 之后同一个 tick）** | **svg: false 0×0** | **svg: true 600×240** |
| t1 microtask | false | ok |
| **t2 setTimeout 0 / t3 / t4** | **从没到达**（浏览器已退出） | 从没到达 |

**t2 之后一条都没赶上 firefox 退出** —— 这就是那句纪律的硬证据：**异步不是让判据变红，
是让判据消失**。所以 Tremor Raw 的图表副本里加了一条分支：传了数值 `w/h` 就绕开
`ResponsiveContainer` 直连 Recharts（Tremor Raw 本来就是"复制进项目"的发行版，改副本是它的正当用法）。
**K 线蜡烛图继续手写 SVG** —— Recharts 没有蜡烛图，硬换会丢高开低收，
而 `rect.k-body` / `line.k-wick` / `g.pred` 那批判据原样保留。
行情总览页的对比条同理，是纯 `div`，不经过 Recharts。

### ③ 白名单仍然只放**扁平文件名**

Vite 默认产物是 `assets/index-<hash>.js`，那会同时踩中两件事：`app.py` 的
`SPA_ASSETS` 不放行（404），以及结构判据把带 `/` 的条目判为可疑形状。
所以构建配置成扁平的 `dist/app.js` + `dist/app.css`（缓存用 `?v=<buildId>`）。

### 判据怎么迁移的

**一条都没删，全是等价或更强的迁移。** 最典型的是 `check_links`：

| | 旧 | 新 |
|---|---|---|
| 读的是 | **服务端发出来的 HTML** 里有没有 `href="graph.html"` | **水合之后跑完 JS 的 DOM** 里有没有 |

服务端 HTML 现在一个 href 都没有（React 渲染的），所以这条**不得不**改 —— 而改完之后
它比原来**更强**：原来证明的是"模板里有这个链接"，现在证明的是"这个链接挺过了 hydration"。
同一批迁移里也顺势露出了一个旧判据的空转口子（探针读 DOM 时 `a[href="graph.html"]` 会
匹配到对话里的术语 chip，那是运行时才建的）—— 所以探针读的是 `a#guideCard[...]`，
**带上卡片自己的 id**。

`graph.html` 和它的整条管线（`build_graph.py` / `verify_page.py` / `graph_template.html`）
这一轮**一行没动**；`guide.html` 只同步了 CSS token 的值，结构和判据都没碰。

### ★按钮那一枪现在**打到了**；剩下没覆盖的是它**回来之后**那半段

`/api/key` 那一整组判据打的是**接口**，而用户走的是**按钮**。旧页面那个 bug
（`keySend()` 发 `JSON.stringify({})`，从来没读过输入框）就是这么活下来的：
点保存 100% 是坏的，而当时 **152 条判据全绿**。现在补了两条渲染层判据 ——
探针点一下「保存」，把 `window.fetch` 临时换成"只记录、不发送"，
于是判据能读到**按钮真发出去的那一枪**（`POST /api/key` + `{"key": <输入框里的值>}`），
并配了两条注入：把按钮从 `send("POST")` 上摘下来、把 `{ key }` 改成 `{}`。

**但"点下去 → `.env` 真的变了 → 页面回执说'已保存'"这条端到端的路仍然没被覆盖**：
回执在 `await` 之后，无头 firefox 那时已经退出了（见上面那张 spike 表）。
那一半由接口判据守着，两半**接不上**是有意的取舍 ——
宁可写清缺口，也不拿"接口是绿的"冒名顶替"按钮是绿的"。

### 行情总览页那条对照：`LICAI_FEED_STUB`

`/dash` 那批判据里最值钱的一条是**对照**（"换掉接口的返回，页面上的数必须跟着变"），
而不是"页面上有 52.3%"—— 后者抓不住"把数字写死在页面里、今天看着完全正确"这种坏法。
但真去东财取数的话，判据跑两遍拿到的可能不是同一份行情，那就成了**拿 A 比 B**。

所以加了一个只给验证用的离线桩：服务端环境变量 `LICAI_FEED_STUB` 指向一份 JSON
（基准价 / 天数 / 振幅 / 种子 / 点名让哪个标的失败），`feed.fetch()` 直接返回构造出来的
日 K。三条边界：

- **桩是服务端读环境变量的，客户端碰不到。** 一个"客户端能打开的桩"就是一台伪造行情的机器。
- **每个标的的数不一样**：种子把 market/code 折进 `zlib.crc32` 里。
  （第一版没折，五个标的长得一模一样 —— 而那批判据**全是绿的**，
  因为它们只验证"页面上的数 == 接口给的数"，五个相同的数照样满足。
  这是"判据全绿而东西是坏的"，靠肉眼看探针输出才发现的。）
  ★顺带一个坑：种子用 `hash()` 不行 —— CPython 的字符串 `hash` 带进程级盐
  （`PYTHONHASHSEED`），换个进程就是另一份数据，判据会时绿时红。
- **`/api/kline` 的缓存要绕过**：不然同一个代码第二次取到的是上一次的缓存，
  "换掉返回、页面跟着变"这条对照就永远看不见变化。

### ★参照物：`/legacy`

根目录那个旧页面**文件没动也没删**，只是改从 `/legacy` 发。留它的理由不是怀旧：
新页面是一整套构建产物，万一构建坏了、或者某条判据说不清是"页面坏了"还是"判据过时了"，
`/legacy` 是那个**已知为真**的参照物 —— 同一台服务器、同一个数字出口，两边一比就知道
问题出在哪一层。

# 这一轮：多智能体博弈 / 分钟级策略 / 关联检测 / 常驻采集

一轮里加了六个包（`agent/datasource`、`agent/intraday`、`agent/linkage`、`agent/agents`、
`agent/sentiment`、`agent/collector`）和五个前端页。下面按"它在做什么"写，不按文件写。

## ① 多智能体：9 个角色、两轮**真**交锋、权重**算得出来**、风控有一票否决

`agent/agents/`。角色：`bull` 多头 / `bear` 空头 / `fundamental` 基本面 / `technical` 技术 /
`sentiment` 舆情 / `risk` 独立风控官 / `pm` 投资经理 / `kg_tutor` 知识图谱讲解 / `psych` 心理。

**"多智能体"最容易做成的东西**是"把同一份数据讲九遍的长文"。这一层挡它的四道闸：

1. **一份证据，九个人看**（`evidence.py`）。同一轮里取**一次**数，按角色分发 ⇒
   "多空看的是不是同一张图"是**结构上**成立的，不靠提示词嘱咐。
   探针并发跑，每个都带墙钟上限 —— 超时**不杀线程**（Python 杀不掉），只是不再等它。
2. **第 2 轮是真的交锋**（`roles._opponent_block`）。多头第 2 轮的提示词里**原样**含
   空头第 1 轮的立场值与原话，反之亦然。它必须**改立场**或**写反驳**，两件都没做就是
   "这一轮没发生"（`_revised()` 判定，并重试一次）。
3. **权重是算出来的**（`weights.py`）。三个因子相乘：

       w_i ∝ base_i × scenario_i × vol_i × calib_i × conf_i     （只对 6 个"投方向票"的角色）
       Σ w_i = 1        score = Σ w_i × (stance_i or 0)

   ① 场景（趋势/震荡/危机，来自 `agent/intraday` 的 regime + 波动率）
   ② 历史校准（读 `agent/ledger.py` 的台账）  ③ 本轮自报置信度（**做了收缩**）
   `compute()` 把每条 `w` 和每个 `stance` **一起发出去** ⇒ 任何人乘一遍能得到同一个数。
   这是"权重不是装饰"的唯一检验方式：**算不出来，那张表就只是长得像权重的说明文字**。
   ★`risk` / `kg_tutor` / `psych` 三个角色权重是 **0**，而且**照实出现在表里**、
   `basis.zero_weight_roles` 说明原因。不是把它们踢出会议 —— 是它们的票本来就不该进
   加权和（风控靠**否决**影响结论；讲解和心理讲的是"这是什么"，没有立场，
   硬给权重只会造一个**看起来在投票**的假象）。"这一票是 0"和"这个角色不在表里"是两件事。
   ★**已知的结构性空缺**：因子 ② 要读台账，而**目前没有任何代码在往台账里写
   角色维度的对错记录**（`weights.record_view` / `record_outcome` **只有定义、没有调用点**，
   grep 可验）⇒ ② 实际恒为 `prior`。这不是 bug（缺数据时降级到先验是设计，`factor=1.0`
   不动权重），但**这一条因子现在没有在起作用**，别把它当成已经在起作用的证据。
   输出里是诚实的：`basis.calibration.roles[*].source == 'prior'`，而且
   `basis.sources.note` 就写了一句话说明这件事 —— 页面上那句"动态权重"要成立，
   得先有人往台账里写角色维度的记录。
4. **风控一票否决**（`risk.py`）。硬条件命中 ⇒ 方向降级成 `flat`；软条件 ⇒ 保方向、
   强制加提示、扣置信度。条件是**数值条件**，不是形容词。

**事件流**（`/api/agents`，SSE）：`agent_round` / `agent_start` / `agent_say` /
`agent_done` / `agent_weights` / `agent_verdict` / `done`。★所有事件在 `done` **之前**
发完。`app.py` 里**曾经**另有一份本地 SSE 包装，已删 —— 见下面"集成层"那节。

## ② 分钟级（5/15/30）：11 个策略，只出一个复合分

`agent/intraday/`，对外只有一个函数 `analyze(market, code, periods=(5,15,30))`。

| key | 名字 | key | 名字 |
|---|---|---|---|
| `orb_break` | 开盘区间突破 | `momentum` | 短周期动量 |
| `orb_fail` | 开盘区间假突破 | `squeeze` | 布林带挤压/扩张 |
| `vwap_revert` | VWAP 偏离回归 | `resonance` | 多周期共振 |
| `rvol` | 相对成交量 RVOL | `atr` | ATR 止损目标位 |
| `volume_profile` | 成交量分布 | `session` | 时段效应 |
| `divergence` | 量价背离 | | |

量价那一半是重点（用户要的是"**基于成交量**的短线"）：`volume_profile.py` 出
RVOL / POC / 价值区，`levels.py` 出 ATR 及由它推的 entry / stop / target1 / target2 / rr，
`regime.py` 出状态与跨周期共振。

三条纪律：

- **`atr` 只出价位、不给方向。** 把盈亏比混进方向判断是倒因为果。
- **合成的帧必须自己报出来。** 返回值里有 `data_source`，前端**必须显示**它：
  `'SYNTH(...)'` 与真行情在别的字段上长得一模一样。只有显式 `LICAI_INTRADAY_SYNTH=1`
  才走合成（离线跑判据用）；取不到真数据时返回 `ok=False` + 人话原因，**不拿合成数据顶上**。
- **NaN/inf/非数一律 `None`，不是 0。** `finite()` / `num()` / `safe_div()` 三个出口同一个纪律。
  `safe_div` 分母为 0 时返回 `None` —— 一个"用 12 个点算出来的 0.87"比"没有"坏得多。

## ③ 关联检测：**采集是主角，分析只做最朴素的一层**

`agent/linkage/`。用户原话：「有异动了列出与它关联的版块、个股的情况，做简单的分析，
注意：这个注重信息的采集，弱化分析。」落成三条：

1. **`collected` 要详实**：哪个源、几行、几毫秒、什么错、快照时间戳、覆盖哪些市场、
   **哪些没去采**（预算用尽 / 代码不在池子里）。这是**产品本身**，不是日志。
2. **分析只到横截面 z、量比、滚动相关、lead-lag 为止**。不预测、不给买卖建议、
   不写长论述。`note` 只说事实，长度压在一两行。
3. **没算的数不许有形状**：样本不够的相关性 ⇒ `rel_value: None` + 一句为什么。

两个出口：`scan(scope='all', codes=None, top=20)` 和 `anomaly_of(code)`。

## ④ 常驻采集器：只采、只存、只记健康度

`agent/collector/`。**是通信采集装置，不是分析装置**：不判断、不给方向、不算关联
（那是 `linkage` 的事）。区别在 `linkage` 是"用户问一次扫一轮"，它是**常驻**、
一轮一轮把索引追加到盘上，让页面能看"采集器在不在跑、最近几轮各采了多少行、哪个源在挂"。

冻结接口三个：`status()`（**只读**，不触发采集、不写盘）、`ring(limit=120)`（→ **裸 list**）、
`once(scope='all')`。★`once/status/ring` **不依赖** `start()` 被调过 —— `app.py` 是惰性
import 它的，它不会、也不该自己起线程。

★两条踩出来的边界：

- **「包还没落地」和「包落地了但坏了」必须分开报**（`NOT_READY` vs `DATASOURCE_BROKEN`）。
  Python 3 的**命名空间包**让"只有目录、没有 `__init__.py`"的包也能 import 成功，
  于是 `datasource.realtime` 抛 `AttributeError`，看着像"包坏了"，实际只是"还没写到这里"。
  把"还没做"报成"做坏了"，会让人去修一个不存在的东西。
- ★**实测成本：一轮 10926 行 / 7 个源 / 约 20 秒，落盘 1.36 MB ⇒ 一天约 1.91 GB。**
  ⇒ **保留期**（2026-09-22 落地，实现在 `store.prune()`、由 `once()` 调用；
  `status()` / `ring()` 这两个只读接口**一行没动** —— "看一眼状态"顺手删盘是最坏的一种脏）：
  - `LICAI_COLLECT_RETAIN_DAYS` 默认 **3**：删「**文件名上的日子** < 今天−3」的帧文件。
    ★比的是文件名上的日子、**不是 mtime**（mtime 被任何一次追加刷新）；3 天是
    「周一还能翻到上周五」的**最小值**，再短跨不过周末。
  - `LICAI_COLLECT_MAX_BYTES` 默认 **8 GiB**（从最老一天起删到不超）：兜底闸，
    因为天数闸挡不住"速率变了" —— `LICAI_COLLECT_INTERVAL=1` ⇒ 速率 ×60 ⇒ 3 天就是 340 GB。
  - 四条边界：只在 `once()` 里；只碰 `frames/` 里匹配 `YYYY-MM-DD.<tag>.jsonl` 的**普通文件**
    （`index.jsonl` 从不看它）；删前 `_inside()` 做 realpath 包含检查（越界记 `denied`，
    不靠"反正不会发生"）；**不删 600s 内被写过的**（`LICAI_COLLECT_PRUNE_MIN_AGE`，记
    `guarded`）—— `unlink` 一个仍被 `open(...,'a')` 持有的文件，会让对面那一轮
    **静默写进空气且 fsync 成功**，这条闸只把窗口从秒压到 10 分钟、**只推迟不阻止**。
  - `once()` 的返回值新增 `prune` 键（`removed/foreign/denied/guarded/failed/kept/
    oldest/cutoff/note`）；**真删了**才在 `msg` 后追加一句 —— **没删的那一轮 `msg`
    与 `_round_msg` 逐字相同**。
  - ★**两笔仍在的账**：① `index.jsonl` **仍然无限涨**（约 0.6–3 KB/行 × 1440 行/天
    ≈ 1.5–4.5 MB/天，比帧小三个数量级但确实无界；削它得先决定「`ticks` 这个累计计数
    在轮转后算什么」，所以这一轮**故意**没动）。② ★**保留期目前没有任何判据守** ——
    而且这不是推测：实施者把 `prune` 换成"无差别删掉 `frames/` 下一切"再跑采集器那套
    判据，**仍然 rc=0、20/20 绿**。原因是结构性的：那条"只追加"尺子只比对**还在的文件**
    的前缀 ⇒ 被删掉的文件**直接退出样本**；而探针造帧时没传 `day=` ⇒ 沙箱里永远只有
    今天的帧，天数闸**结构上**碰不到它。⇒ 已排期补一条（必须自己造出过去日子的帧文件，
    并配负控证明"该留下的一个没少"）。

## ⑤ 数据层：从 akshare 换成四个直连上游

`agent/datasource/`，**本数据层的唯一出口**（上层只 import 这个包，不碰里面的源模块）。
契约是十个函数 + `CANON`：`daily / minute / realtime / snapshot / boards /
board_members / stock_boards / capital_flow / trade_calendar / health`。

为什么换：`agent/feed.py` 那条链**整条都是 akshare**，而 akshare 的 A股/港股日K 主源是
东财，且**它是按 akshare 的列名设计的**：分钟线、板块、全市场实时这三件它一件都没有。

★★**这里有一条必须先说的话，否则你会照着一个错的理由去改代码**（我差点就这么干了）：
本文档早先写过"东财全部 API 主机 0.2 秒就被断连"，**这句话作为常驻事实是错的**。
分两层看：

- **层一：Clash 代理。** 本机 `http_proxy=127.0.0.1:7897`，国内站走它一律 **502**。
  `agent/datasource/_base.py` 的 `drop_proxy()` 就是为这个存在的。这一层不是"东财坏了"，
  是"我们绕了远路"。
- **层二：东财主机族。** `agent/datasource/adata_src.py` 记的实测是
  `push2*` 一族 `RemoteDisconnected`、`datacenter*` 一族 200（⇒ 分界线是**主机族**，
  不是整站）。**但 2026-09-22 晚些时候复测，`push2*` 一族 8/8 轮全部 HTTP 200 真 JSON**
  （`stock/get`、`clist/get`、`kline/get` 含 `klt=5` 五分钟线，均 0.05–0.11 秒，
  带不带 UA/Referer 都一样）⇒ 这条条件是**随时间变的**，不是稳定的。

⇒ 所以：(1) 别把"东财挂了"当设计前提，要用之前**先自己量一遍**；
(2) 反过来说，也**别**因为现在通了就把多源链拆掉 —— 这一层链的价值恰恰是
"某个源哪天不通了"时有下一家。**易变的结论只能用来决定"先试谁"，不能用来删掉备选。**

源链**逐源降级，全挂了才报错**，且把每个源的**真原因**一起抛上去：

| 能力 | 链 |
|---|---|
| 日 K（A股/ETF/指数/港股/美股） | **腾讯 → 新浪 → 同花顺 → akshare(feed)** |
| 日 K（加密） | `feed.fetch('crypto', …)`（**不重写**） |
| 分钟线 | 见 `datasource/` 内的源表 |
| 板块 / 全市场快照 / 资金流 | 见 `datasource/` 内的源表 |

★两处**修正过的**早先结论（别照抄旧说法）：**港股/美股的分钟线拿不到**
（腾讯 `fqkline m5` 不支持）；**东财不是整站死了**，死的是 `push2*` 那一族主机 ——
`datacenter.eastmoney.com` 仍然可达。
★**板块代码空间不通用**：腾讯是 `pt01801120` 这种形状，东财是 `BK0438`。
两套并存时**不能互查**，映射表还没定（待拍）。

## ⑦ 集成层这一轮修掉的三个**静默**缺陷

都是"不报错、页面上看不出来、而能力已经没了"那一类。写在这里是因为它们的形状可复用。

1. **`ContextVar` 不跨线程 ⇒ 风控的两条 veto 条件在生产里结构上打不响。**
   请求上下文（持仓 `_REQ_HOLDINGS` / 画像 `_REQ_PROFILE`）是 `ContextVar`，
   而 `ContextVar` **每线程一份、且不会自动传给新线程** —— `ThreadPoolExecutor.submit(fn)`
   拿到的永远是**默认值**。探针正是被 submit 到池线程里跑的 ⇒ 在 worker 线程里老老实实
   `set_request_holdings(...)` **照样没用**，`analyze_portfolio` 读到的一直是 `None`，
   风控静默走"还不知道你的持仓"的降级分支。
   **任何同线程的判据都量不出来**（实测：带持仓走 HTTP，`concentration.value` 仍是 `null`、
   `unknown=true`，与不带持仓**逐字相同**）。修法在 `evidence._with_timeout` 里
   `contextvars.copy_context()` + `submit(ctx.run, fn)`；改这一处，将来加的探针全覆盖。
2. **`app.py` 里那份重复的 SSE 包装**（`_agents_stream`）**从来没有设过 holdings/profile**，
   而且它的 `except` **只发 `error`、不发 `done`** ⇒ 真出异常时前端一直转圈。
   同一件事留两份实现，就是"一处做对了、另一处没人发现"的标准形状 ⇒ **删掉本地那份**，
   直接调 `agents.sse_stream`。
3. **`/api/collect/ring` 的 `limit=0` 被 `or` 吞掉**：`int(b.get('limit') or 120)` 把
   **合法的 0** 当成"没给" ⇒ 变成 120 ⇒ "最近 0 轮"返回**全部**记录。
   `or` 只该兜 `None`，不该兜 0。同类：这条路由**声明了 GET** 却只读 `get_json()`
   ⇒ `?limit=0` 整个被丢掉、静默退回 120（同一个病的第二个面，已按 body 优先 / query 兜底修）。

（另两处同类边界修：`tools.clean_holdings` 收到 `123` 这类非可迭代对象会在迭代那一刻
抛 `TypeError`，而它被三个接口调用 ⇒ 一个手写客户端的笔误变成三个接口的 500；
`uicopy` 会把采集器那条 hint 里的 `crypto` 改写成「加密货币」，而用户**照着页面那句话敲**
会必然再失败一次 —— 现在 `/` 分隔的机器 token 串整体豁免改写，散文里的照旧汉化。）

### `⊘` 的一种真实来源：firefox 截完图不退出（2026-09-22 修）

`verify_page.py` 那一层要开真 firefox 截图，而本机 firefox **有时**（与并发/资源有关，
不是恒定属性）**图截出来了、进程不退出** ⇒ 那个写死的 `timeout=240` 抛 `TimeoutExpired`，
而对面**没接住它**（只有 `finally`、没有 except）⇒ 异常冲出 `main()`、退出码 1。
**形状与"图谱页真的坏了"逐字相同** —— 于是 `check_pipeline_untouched` 会红成
「图谱页被碰坏」，而图谱那几层当时全绿。这是最坏的一类红：**红得响亮、指向错的物体**。

修在**消费端**（`verify_agent.py`，不动 `verify_page.py`）：特征取**窄**（`TimeoutExpired`
**与** `--screenshot` 同时出现），然后**藏掉 firefox 重跑一趟**，按对面的三态码落
`⊘ / ✗ / ✓` —— 让对面自己回答"除浏览器层外有没有真红"，而不是在这边猜。

- ★**不是"超时就算过"**：放宽成"非零退出就算环境问题"会把**任何真红**一起洗掉，
  而那正是这条判据存在的理由（它当初就是为了不让"没跑"悄悄变成"通过"才写的）。
  失败优先的协议在这里是关键：真有红时对面必返 1，只有"没跑"才返 3。
- ★**证据三层**，缺一层都不算落地：① 四臂桩判据（喂合成的 stderr，量**分类**）
  在干净副本上全绿；② 一条注入把特征放宽 ⇒ **恰好**打红 C 臂；③ **确定性装置** ——
  PATH 上放一个**只睡不截图**的 `firefox` shim ⇒ 240 秒超时必然发生，实测真的走到
  新分支、落 `⊘`、且理由里点名的是**环境**而不是图谱页。
- ★代价说清楚：这条判据只在**已经红了的路上**多跑一趟（≈2 分钟，且那趟会重建图谱产物
  ⇒ 属于**慢判据**，别混进秒级自测里）。
- ★同一天还有一次**反观测**（同代码、真 firefox 跑出 `rc=0`、全绿）—— 所以它是
  "时有时无"，判据不能赌它不发生；要赌的是"真发生了也能分辨"。
- ★**本轮在正式路上真撞上了它**（2026-09-22，`.venv/bin/python verify_agent.py --no-render`）：
  **341 行判据 = 340 通过 + 1 条 `⊘` + 0 条红**，那条 `⊘` 就是本节这条

### ★"没跑成"的退出码：修掉一个把 ⊘ 折叠成"通过"的洞（2026-09-22）

上面那节说 `verify_page.py` 的三态协议是 `0/1/3`、而消费端必须把 `3` 登记成 `⊘`。
**但那是子脚本的退出码**；本节说的是**父脚本自己交出去的那个码** —— 它此前是**两态**：
`main()` 收尾的"有判据没跑成"那一支写的是 **`return 0`** ⇒

```
$ verify_agent.py --no-render && echo 成功了
...
其余 345 条判据通过；有 1 条没跑成（见上）
成功了                       ← ★渲染层一条都没跑，而这里印的是"成功"
```

这正是 `Report.skip` 那段 docstring 里点名的事（"「没跑」最自然的归宿就是**悄悄算通过**"），
只是它发生在**退出码**这一格 —— 报告那一格早就守住了（`⊘` 单独印、收尾再报一遍）。

- **修法**：三态提取成一个纯函数 `exit_code(rep)`（`failed` ⇒ `1` / 只有 `skips` ⇒
  `PAGE_SKIP_RC` / 全过 ⇒ `0`），**失败优先的顺序就是这条规则本身**：
  "没跑"只能把全过降级，**不能把红升级成没跑**（对调之后，一次真红会被读成
  "环境问题、重跑就好"——而 `&&` 后面接的东西会照跑）。
- **配了一条判据**（`check_exit_code_protocol`，**四臂**，走正常路）：红⇒1、只"没跑"⇒3、
  全过⇒0，**外加第四臂"红 + 没跑"⇒1**。第四臂不是凑数：只量前三臂的话，
  把顺序对调**照样全绿** —— 而顺序恰恰是这条规则里最要紧的那半句。
- **配了一条注入**（打 `verify_agent.py` 自己，把两段对调）：实测**只打红第四臂**、
  只红这一条判据，`故障注入：1/1 条成功打红`，且文件**逐字节还原**。
  ★这条注入本身也是个守卫：哪天有人把判据砍成只剩"有 skip ⇒ 非 0"，
  它**照样绿** —— 也就是说"第四臂有没有用"是有东西量着的。
- ★**它量的是纯函数 + 四条人造报告，不是端到端**：`main()` 收尾那几行有没有真的去调
  `exit_code` **不归它**（那一格靠人读一眼）。别拿这条判据去填"整条路都被量着了"。
- ★**这条改动会让"有 ⊘ 的那一轮"从 `rc=0` 变成 `rc=3`**。本仓库里没有任何脚本链式
  调用 `verify_agent.py`（查过：只有 README 与源码注释引用它），所以影响面是
  人/agent 手敲的那一条命令；对"接在 `&&` 后面"的用法，这是**从假通过改成如实报告**。

判据有**三种**状态，不是两种：

| | 含义 | 计不计入失败 |
|---|---|---|
| `✓` | 跑了，过了 | — |

> 注入写坏了会**自己报警**。实测踩到一次：有一条注入只替换了那行代码的前半截，
> 注释尾巴留在原地变成一行裸代码，整个 `<script>` 语法崩掉、探针一个字节都送不回来，
> 于是那一批判据**整批消失**。harness 报的是「**判据不存在**」而不是「判据没变红」——
> 这个区分很要紧：后者会说"判据是装饰"，而真相是**注入自己坏了**。
> 教训是**整行连注释一起替**，别只替前半截。

注入结果有**三种**，和判据一样：`✓` 打红 / `✗` 没打红（判据是装饰）/ `⊘` **没验到**
（对应判据因环境前提没跑成）。第三种必须单列：一条**没跑**的判据在 `rows` 里长得
和"跑了且失败"一模一样（都是 `False`），harness 若只看 `not r[1]` 就会替一条
**从没跑过的判据**背书，欢呼"这条判据是真的"—— 坏的是**注入自测本身**。

> **必须用 `.venv/bin/python` 跑。** 系统 `python3` 里没有 akshare/einops，
> 服务照起、页面照渲染，但 `feed.fetch()` 会在取数那一步就抛 `NO_AKSHARE`，
> 于是"源链会降级"在一条**从没跑过循环**的路径上判绿、"摘要里没有长数组"
> 在一条**压根没取到数**的错误摘要上判绿 —— 全是假绿。
> 脚本会在开头自己检查并 `execv` 换解释器。

### 这一轮踩到的坑（都写进脚本结构里了）

1. **注入了，但被测代码没变。** 第一版 11 条注入全部"没变红"，看着像判据是装饰 ——
   其实是**注入是装饰**：文件改在磁盘上，而 Python 早把旧代码缓存进 `sys.modules` 了。
   现在注入后按依赖顺序 `importlib.reload()`，走 HTTP 的那几条则在**注入之后另起服务**
   （`app.py` 只在进程启动时读一次代码）。
2. **判据空转。** `★不该拿到 /.env → 404` 一直是绿的，因为 **`.env` 在本机还不存在**，
   而 `send_from_directory` 对不存在的文件一律 404 —— 白名单开成筛子它照样绿。
   现在补了一条读**白名单本身**的结构性判据（与文件在不在无关），并显式报告哪些敏感文件缺席。
3. **判据读到了脚本。** 主页面里的 JS 源码含 `a.href = 'graph.html'` 和
   `querySelector('a[href="graph.html"]')`，用正则抓 `href="..."` 会把**字符串里的**
   那个也当成链接 —— 于是把卡片链接改坏了判据照样绿。现在先剥掉 `<script>` 和注释。
4. **`and` 短路把判据吞了。** `check_static(sub) and check_links(sub)` 一短路，
   `check_links` 根本不跑，注入打上去只得到一句「判据不存在」。**没跑的判据不算判据。**
5. **端口上坐着别人。** 服务"起来了我怎么知道"原来只是反复试连 —— 连上的可能是
   别的进程。本机实测踩到：一个忘了关的测试 app 占着口，整轮判据全打在它身上。
   现在起服务前先确认端口是空的。
6. **"没配 key"这条路径没人验过。** 它跑的是**另一条代码路径**（主服务带着打桩 LLM，
   整条真实调用被绕过去了），而这恰恰是用户第一次打开时最可能遇到的状态。
   现在单独起一个 key 显式为空的进程测它 —— 判据的形状是「不 5xx、不挂死、
   给出结构化 `NO_KEY` 事件 + 提示」。注意**「HTTP 200」这条判据在这里是绿的**，
   它拦不住"错误被悄悄吞掉、页面干等"这种坏法。
7. **一条判据红绿由 A 决定、结论却记在 B 头上。** `predict_kline` 是「**先取数、再推理**」，
   两段失败都给 `ok: False`。原来的判据只认 `ok is False`，于是**网线一拔它照样绿**，
   还打印「模型当前不可用」这句错话。现在先按错误码分清是哪一段（引擎码 vs 取数码），
   分不清的走 `⊘`。
   同族的问题：模型链路原来**只有经过工具层这一条路**，所以它测的其实是"取数+推理"
   合起来的结果。现在补了 `check_engine_direct` —— **喂合成 K 线、不联网、不经过大模型**，
   和 `check_feed` 用假源同一个道理：**模型链路的对错不该取决于外网今天的心情。**
   同一招后来也用在了工具层：`check_predict_offline` 把 `tools._get_kline` 换成合成数据，
   于是 `predict_kline` 整条路（含**数据通道**）也搬到了不看外网脸色的一侧。
8. **一条成功的注入会把坏模块留下，污染后面每一条注入。** 本模块顶层不 import `runner`，
   而 `reload_agent()` 的名单里也没有 `runner` —— 于是**头一条**打 `runner.py` 的注入
   会生效（那一刻 `runner` 还没进 `sys.modules`，是被**注入之后**才第一次加载的），
   但它一旦进了 `sys.modules` 就再没人管：`Fault.__exit__` 只还原磁盘，内存里那份坏代码
   一直留着。实测症状是**下一条**注入报「找不到判据」—— 因为 `predict_kline` 还在被
   上一条毒害，走到 `_sanity` 就 `BAD_OUTPUT` 了，判据根本没轮到执行。
   修法两条：`runner` 加进 reload 名单（且排最前，因为 `tools` 里
   `from runner import ... ENGINE` 要先换掉 runner 才能重绑），以及
   **把 reload 放进 `finally`** —— 原来只写在 `except` 分支，所以"成功"的注入反而
   是污染源。**注入要能撤回来，才算一次注入。**
9. **一条判据从没跑过，于是它里面的崩溃也没人知道。** `check_predict_output` 里
   `时间戳是升序的` 传的 `detail` 是个**列表**，`detail[:150]` 对列表做的是切片，
   拼进 `print` 就 `TypeError` —— 判据自己把整轮验证打崩了。它一直没暴露，是因为它前面
   那条路永远先失败并走 `skip`，这行代码**从来没被执行过**。这和坑 6、坑 7 是同一个形状：
   **"没跑"会把"坏"藏起来**，而且这次藏的是一个能让脚本崩掉的东西。
   修法：`Report.add` 统一 `str(detail)` 再截断（判据里顺手传列表/数字当证据是常事）。
10. **判据判对了，证据是假的。** `check_key_precedence` 要在"注入 `.env` 之后"看
   `PORT` 和 key 有没有被顶掉，可它的 `detail` 字符串是在 `finally` 恢复现场**之后**
   才拼的 —— 于是明明判对了，打印出来却是 `PORT=None（应当是 12345）`，
   而且更糟的是把**用户真 key 的掩码**打进了日志（掩码也是泄露，
   6+4 个字符足够去别处对上了）。判据的**输入**在 `try` 里，**证据**必须在同一个作用域里
   取好、存下来再用。**一条报错信息说谎的判据，比没有判据更容易骗人。**
11. **注入打在了同名的另一处。** `max-width:clamp(1180px,78vw,2200px)` 这轮同时出现在
   `.bar` 和 `main` 上。"布局退回写死 1180px"那条注入只写了前半截，`count=1` 于是命中了
   **`.bar`** —— 判据确实红了，但红的是**对齐**那条，而它自己那条（主栏宽度）照样绿，
   自测报的是「判据没变红」，看起来像"判据是装饰"，真相是**注入打偏了**。
   修法是把注入锚到 `main{max-width:...` 这种带选择器的整串上。
   **同族：写注入前先数一遍目标字符串在文件里出现几次。**
12. **一条恒真的判据。** 「带上『怎么办』的提示」原来只断言 `hint` 非空 ——
   任何字符串都满足，注释写得再对也是空转。现在它必须提到"网页"和"卡/填"，
   也就是**钉住"提示指向用户真会走的那条路"**这件事本身：原来的提示让人去
   `.env.example` 复制文件（站外操作），而页面上就有输入框。

```
      ├─ parse_terms.py ──► terms.json          （词表五项检查）
      │
      ├─ build_graph.py ──► graph_data.json     （两层一致性 + 布局 + 自检）
      │        └─ 读 graph_template.html 内联数据 ──► graph.html
      │
      └─ verify_page.py                            （语法 + 面板 + 点开收起 + 真浏览器）
```

**改词表只改 md，然后重跑脚本。** 在 md 里删一个词、而别的词还用对比/前提指着它，
图上就多一条断边，`parse_terms.py` 会喊出来 —— 这就是"单向投影"的意思：md 是源，其余全是产物。

`--selftest` 是**证明这套尺子不是空话**的那条：它往页面里注入 **19 条故障**
（数据/页面层 15 条 + 真浏览器渲染层 4 条），**每条都必须让判据变红**。
含真 firefox 跑一遍页面再读屏幕上的色块，覆盖桩看不见的那一层
（CSS 优先级、栅格行高、viewBox 缩放、窄屏 position:fixed 面板）。

## 数据层（智能体用的就是它）

`graph_data.json` 里每个词条带 `f`（五栏字段）、`vs`（辨析对象）、`deg`、`root`（无前提 = 教学起点）、
`cat`/`catName`/`fam`；分类节点带 `members`/`refs`；`links` 带关系名。
**这些字段就是给智能体走图用的**，无需再从正文里解析自然语言 ——
`agent/graph_kb.py` 只读这份产物，不碰 md、不重跑管线。

## 几条设计取舍（不是随手写的）

- **布局在构建期用 numpy 烘焙好，不在浏览器里现跑** —— 换来确定性（同种子同图）、
  可验证（布局是纯数字，判据能直接算）、首屏即静止（没有节点乱飞的动画）。
  ★布局自检的**闸门只有两条**：最近邻最小 > 8（没有节点叠在一起）、
  同族平均距离 < 异族平均距离（真的聚成簇）。
  「包围盒宽高比」和「中位最近邻」**只打印、不是闸** —— 它们是读数，不是判据，
  而且会随词表变（加一个词就变）。所以**不写进文档**：要看就以 `build_graph.py`
  收尾那几行为准。文档里抄一份数字，等下一次改词表就成了假的。
- **解释必须拆成字段，不能写散文** —— 后面要接智能体做对话式，散文到时整份要重做。
  （现在这个智能体就是那条"后面"。）
- **面板用侧滑抽屉，不用 modal** —— 面板里的关系是**可点的 chip**，modal 会把这条路堵死。
- **16 个二级类塌成 7 个色族** —— 16 种颜色人眼分不开，7 种可以；字母仍逐个标在节点和面板上，
  颜色只负责"一眼看出这是哪一大片"。
- **「对比」边不对称是对的，不是 bug** —— 它是最邻近关系：混合基金的最近混淆对象是股票基金和债券基金，
  而股票基金的最近邻是债券基金。**最近邻天然不对称**。
- **不用 Google Fonts CDN，而且这条现在有判据守** —— 字体走系统栈（本机有 Noto Serif SC /
  宋体就用，没有就落到 Georgia / Songti SC / serif）。判据是「产物里**外部引用形态**计数 == 0」：
  先剥掉 `<script>`，再数 `<link href=http` / `<script src=http` / `<img src=http` / `url(http`
  这四种形态（只数裸 `http` 会把 JS 里的 SVG 命名空间算进来）。单文件页要在断网、内网、
  `file://` 下都长一个样，引一个 CDN 就等于"网不通时它是另一副样子"，而那种差别是**静默**的：
  页面上看不出少了什么，只是字变了。
  ★这条以前只是文档里的一句约定 —— 产物里其实一直挂着一条 `fonts.googleapis.com` 的 `<link>`，
  同源的 `index.html` 反倒没引。**文档说"不用"、产物里在用**，两个说法对着，谁也没发现。
  现在阈值是 0，往产物里塞一条外链就会当场变红。
- **两套主题的三档文字色都过 WCAG AA（4.5:1）** —— `--ink` / `--ink-2` / `--ink-3` 对
  `--paper` / `--card` / `--card-2` 共 9 对，浅色和深色各验一遍。`--ink-3` 原先在浅色下
  只有 3.28~3.61、在深色的 `--card-2` 上 4.20，**都不及格**，是为过线才调过值的。
  hover / focus 态不另立判据：它的底色就是这三张之一，由「底色完整性」那条守
  （凡 `background` 声明必须落在三张底或一张显式例外表里，表里要写清"上面压不压字"）。
  ★已知缺口写在判据里：页头的底是 `color-mix(纸 88%)` + `backdrop-filter:blur`，**不是** token 直出；
  未滚动时合成结果等于 `--paper`，一旦页面溢出、有内容滚到页头底下，这条判据就看不见了。

## 已知取舍

- 对比/前提是**人工标注**的教学关系，不是从语料里算出来的。
- 「属于」列推导出的 73 个分类节点只有一句说明，不展开成长解释（它们不是词条）。
- `解释-v1.md` 是早期 19 条的文风试点，**已被 `解释.md` 取代**，未入库。
- Kronos 只吃价格序列，**不含基本面/新闻/政策/资金面**；它给的是方向不是承诺。
- **模型给的 high/low 有一半不自洽**（实测 53%），我们按 `max/min` 重建了包络，
  所以图上高/低点的可信度**低于收盘价那条路径**。详见上面「实测」一节。
  这也意味着 `pred_high` / `pred_low` / `pred_max_up_pct` 这几个摘要字段是**重建值**。
- ★**涨跌色语义（A 股红涨绿跌 / 欧美绿涨红跌）这一档没有任何判据**（2026-09-22）。
  主题那一档是有的（探针把启动值带回去，量"页面真的启动成了什么"）；市场这一档
  `theme.ts` 里**故意没有** `window.__bootMarket` —— 不假造一个没人读的启动值。
  所以"开关接线到了产物"目前只有**三层证据、零判据**：
  ① **源码**：`Shell.tsx` 里那两处（import + `<MarketSwitch />`，摆在 `ThemeSwitch` 之后、
  `#badges` 之外 —— 中间那条故障注入的逐字锚点插不得）+ `theme.ts` 的三处值入口
  （首帧内联脚本 / `main.tsx` 顶层 / `useMarket`）；
  ② **产物是新的**：`check_dist_fresh` ✓（`web/dist` 三个文件与现构建逐字节相同）
  —— 它保证"产物不是旧的"，但**保证不了"这个开关在产物里被渲染了"**；
  ③ **SSR 真渲染**（`react-dom/server` 把 `Shell` 渲成 HTML）：页头里真有
  `aria-label="涨跌颜色"` 那一组、排在主题那组**之后**、默认 `红涨绿跌` 按下。
  ★**没验的是像素那一层**：`[data-market="us"]` 有没有真把 `--up`/`--down` 对调过来、
  对比度、窄屏实际怎么换行 —— **没人替它把关**。
  ★顺便记一把尺子：**产物 grep 对"接线"这件事没有分辨率** —— 组件是死代码时
  那一串文案也照样在 `dist/app.js` 里（实测加渲染点前后逐字相同）⇒ 一个"改前改后
  读数一样"的尺子证明不了改动。`grep` < SSR 组件树 < 真 firefox 是**三个强度不同的格**，
  别把中间那格写成最后一格。

## 附录：资讯采集重依赖安装（可选）

资讯采集（`agent/news/`）是**三层降级**的结构，这个附录只讲层2/层3怎么装。
**什么都不装也一切正常**：层1（akshare 新闻源）随主 `.venv` 就有；层2/层3没装时，
对应的源结构化地落进 `degraded[]`，站点**静默退回 akshare 层，没有任何东西会坏**。
`third_party/`、`.venv-collector/`、`data/news_cache/` 都在 `.gitignore` 里，
装与不装不影响 git 状态。（验证走 `LICAI_NEWS_STUB` 离线桩，**只认服务端环境变量**
—— 同 `LICAI_FEED_STUB` 的纪律：一个客户端能打开的桩就是一台伪造新闻的机器。）

### 层1（默认，无需安装）：akshare 基线源

`data/news_sources.json` 是策展的源清单（**真源**，下表只是它此刻内容的抄本）。
默认 `enabled: true` 的是四个 akshare 源，零新依赖：

| 源 id | 标签 | akshare 函数 | 域 |
|---|---|---|---|
| `em-individual` | 东财·个股新闻 | `stock_news_em` | symbol（给了标的才打） |
| `cls-telegraph` | 财联社·电报 | `stock_info_global_cls` | global |
| `em-global` | 东财·全球快讯 | `stock_info_global_em` | global |
| `sina-7x24` | 新浪·7x24 | `stock_info_global_sina` | global |

### 层2（可选）：crawl4ai —— 任意国内外网页

crawl4ai 会拉 playwright + chromium（数百 MB），而主 venv 是 uv 建的（**没有 pip
模块**），torch/akshare 的依赖树也不该和浏览器栈搅在一起 —— 所以它装在**独立的
`.venv-collector`** 里，绝不进主环境：

```bash
cd /home/ylf/licai-agent
python3 -m venv .venv-collector        # uv venv .venv-collector 也行
.venv-collector/bin/pip install crawl4ai
.venv-collector/bin/playwright install chromium
```

- **可用性怎么探测**：`subproc_src.crawl4ai_available()` 先看 `.venv-collector/bin/python`
  在不在，再用它跑一次 `import crawl4ai` 的 subprocess（30 秒超时），退出码 0 才算装了。
  探测结果进 `/api/status`（页面上能看到各层状态）。★探测结果有**进程内缓存**，
  装完**重启服务**再探最稳。
- **env 覆盖**：`LICAI_COLLECTOR_VENV` 直接指到另一个 collector python 可执行文件
  （验证脚本拿假 worker 打靶时靠它，不碰真环境）。
- **调用方式**：主进程**从不 import crawl4ai** —— 用 collector python 起
  `agent/news/_c4a_worker.py`，stdin 送一行 JSON 请求、stdout 收一行 JSON 结果，
  60 秒超时杀进程。worker 崩了/超时了/被反爬挡了，主进程只看到一个结构化的
  `{ok:false, error:...}`。
- **装好之后**：把 `data/news_sources.json` 里两条 crawl4ai 源（`c4a-cls-web`
  财联社·网页电报、`c4a-jrj` 金融界·首页）的 `enabled` 翻成 `true`。
  它们**出厂就是 `false`** —— 没装就跑不起来，开着只会每轮白打一次再降级。

### 层3（可选）：MediaCrawler —— 国内社媒（微博/知乎等）

MediaCrawler 不在 PyPI 上，是一整个应用，clone 进 `third_party/`：

```bash
cd /home/ylf/licai-agent
git clone https://github.com/NanmiCoder/MediaCrawler third_party/MediaCrawler
cd third_party/MediaCrawler
python3 -m venv .venv                  # 它自己的 venv
.venv/bin/pip install -r requirements.txt
.venv/bin/playwright install
```

- **每个平台登录一次**：cookies 按平台存放在
  `third_party/MediaCrawler/browser_data/<platform>_cookies.txt`
  （MediaCrawler 自己登录后写在那，是它的约定位置）。用哪个平台（weibo / zhihu / …）
  就为哪个平台跑一次它自己的 CLI 扫码登录（worker 走的也是 `--lt qrcode` 这条路），
  cookies 落盘之后，后续调用不再需要人。
- **可用性怎么探测**：`mediacrawler_available()` 看 `third_party/MediaCrawler/`
  目录在不在，并**按平台**报告 cookies（对应文件存在且 >10 字节才算有）。
  缺某平台的 cookies 不静默空转 —— 采集时明说「缺 weibo 的 cookies」。
- **env 覆盖**：`LICAI_MC_HOME` 指 MediaCrawler 目录位置；`LICAI_MC_PYTHON` 是
  **它自己的 `.venv` 不存在时**的兜底解释器（优先级：MC 自己的 `.venv/bin/python`
  → `LICAI_MC_PYTHON` → 主 `.venv`）。
- **调用方式**：同样是 subprocess JSON worker（`agent/news/_mc_worker.py`）。
  跑一次要起浏览器，外层超时放宽到 120 秒（worker 内部跑 MediaCrawler CLI 再留
  300 秒）；worker 把 MC 落盘的 JSON 按候选字段名防御式读回、归一成本站 item 形状。
- **装好之后**：把 `mc-weibo`、`mc-zhihu` 两条源翻成 `enabled: true`。

### 缓存（`data/news_cache/`）

- 文件缓存，按天分目录：`<yyyymmdd>/<sha1(源id|symbol|terms)>.json` ——
  同一个源对不同标的/不同关键词是**不同的缓存条目**。
- TTL **900 秒**（真源是 `news_sources.json` 的 `ttl_sec`，改那里就改这里）；
  过期当未命中、重打并覆盖。没有后台清理线程（本站的纪律），
  >7 天的日期目录在写入时惰性顺手删。
- 落盘是原子的（tmp + `os.replace`）。
- env 覆盖：`LICAI_NEWS_CACHE` 指到别的目录（验证脚本指临时目录，不脏仓库）。

### 设计原则（一段话）

资讯采集是**三层降级**：akshare 基线（随主 venv 就有、永远可用的地板）→ crawl4ai
（任意网页）→ MediaCrawler（国内社媒）。上面两层装在**独立环境**里、经 **subprocess
隔离**（stdin/stdout 各一行 JSON、带超时），主进程**零重依赖** —— 不 import
playwright、不碰 MediaCrawler 的依赖树，uv 建的主 venv 一个包都不用多装。任何失败
（没装 / 超时 / worker 崩 / cookies 过期）都收敛成结构化的 `{ok:false, error:...}`
落进 `degraded[]`：部分源挂了整体仍然 ok，全挂才明说没拿到 —— 采集层的故障
**永远不拖垮对话链路**。并且这一层**只采不析**：收集 → 归一 → 去重（URL + 归一
标题两级）→ 按时间排序；多源同题并进 `seen_in`（同一条新闻出现在几个源里本身就是
热度信号），不做任何观点性加工 —— 怎么用是上层（舆情 Agent / 异动雷达）的事。
